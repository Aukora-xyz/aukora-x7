# What the round 11 lab trusts

**Succession preserves exactly the laws we pinned, including our mistakes.** A wrong law is inherited until a stronger set replaces it. Every later set must still entail the old statement, so a stronger set can further restrict behavior and cannot repeal that statement. The theorem concerns the carried model. The successor file is linked to it by a digest and by tests. The checker cell is trusted. Succession raises the stakes on both. [Succession law](RatchetModel.lean)

Round 10 pinned one named contract in its current checker. A successor is other software, and round 10 gave no guarantee that it would pin that law set. Round 11 requires both a proof of the new set on the carried model and a universal proof that the new set entails the current one. Its root contract also constrains the carried model's own future install step. The checker uses a syntactic name to refer to this contract. The definition of succession therefore needs no recursive semantic definition. The admitted predicates and foundation fingerprint persist in the raw record. The identity digest identifies the law. The universal implication establishes its strength. There is no separate amendment event or two-step confirmation. A new genesis begins a different record. [Ledger gate](Ratchet11.lean) · [Kernel statements](RatchetModel.lean)

**Continuity depends on retaining the record and using the checked initialization.** The compiled adapter hashes its actual embedded declaration snapshot. Replaying the old record with a changed snapshot produces a different fingerprint and blocks the old certificate. An arbitrary replacement file could fabricate a context, omit the check, discard the record, or implement a different machine. An older core has no proof about the behavior of such a file. SHA-256 collision resistance, correct snapshot initialization, the Lean-to-Wasm toolchain, the adapter and host execution remain trusted. Independent state migration and enforcement against a hostile host remain outside the theorem. [Initializer and law identity](RatchetChecker.lean) · [Wasm section reader](ModelSection.lean)

**Proof malleability is accepted.** The owner's hybrid grant authorizes a candidate file digest. Its unique model section binds the model bytes, including the child's declared laws. Multiple valid proof terms can justify the same install. For example, changing a bound-variable name preserves typing. Distinct submitted bytes give distinct record heads under the digest assumption. The grant is single-use. This makes the choice of proof visible in the record and permits alternative valid derivations without a new owner signature. Round 10's independent test found eight accepted changes among 440 single-bit proof mutations. [Round 10 test](../logs/repro10/mythos-malleable.mjs) · [Wire layout](WIRE.md)

## Checked source and trusted declarations

The bundled Lean 4.19.0 kernel checked the source theorems. The runtime uses vendored Lean4Lean, a binary parser and a serialized foundation of **3,571 declarations in 4,676,668 bytes**. It trusts **506 prior theorem statements**, **21 opaque declarations** and the explicit axiom `Classical.choice`. Its other declarations comprise 2,273 definitions, 261 inductive declarations, 432 constructors and 77 recursors. The assembled candidate theorem and the whole root-law theorem are carried as terms. Earlier component theorems enter the snapshot by type. Agreement of the serialized environment, runtime type checker and native Lean kernel is a trust assumption. [Declaration inventory](trust/checker-declarations.tsv) · [Exporter](tools/Export11.lean) · [Native controls](tests/RatchetCheck.lean)

The carrier allows 1–64 fresh, safe, monomorphic, nonrecursive definitions in the `R9Candidate` namespace. Each carried set is an explicit finite manifest. Its labels name the clauses used by the checked one-law or conjunctive-extension constructors. The leading predicate can use closed terms over pinned declarations. Remaining bodies may use earlier definitions in the same package. General source compilation, new inductives, new recursive definitions, universe-polymorphic declarations and new computation rules require additional machinery. The example stronger set adds a predicate expressible in the existing language. The fixed foundation also binds all trusted component statements, so even an unused declaration change creates a different foundation. ## Evidence, keys and runtime

A recorded observation is the host's word. The core cannot establish a claim's truth, whether the tool result was honest, whether its class was chosen honestly, or whether the host ran the recorded query. A host must submit the separate refusal-and-halt event to enter the safe state after a refused act. Refused frames themselves preserve the state. A lost owner key prevents the host from furnishing a valid clear or recovery rebind. Theorems describing well-formed inputs and correct verification do not recover missing keys. [Frame grammar and legal set](WIRE.md)

Every signature law is conditional on the concrete Ed25519 and ML-DSA-65 verification results. Key custody, entropy, cryptographic correctness, unforgeability, side-channel resistance and digest assumptions remain external. Successful Wasm tests concern the specific files and inputs exercised here. The adapter, compiler, linker, host persistence and finite runtime resources remain external to the proofs.
