# Cloudflare edge

English | [中文](README.zh.md)

This is the edge adapter for the browser runtime in this repository. It does not connect to a local host machine, implicitly import a local mirror, or change existing services; it uses its own Durable Object namespaces and bucket.

## Current status

A deployed Worker requires owner authentication, provider-secret provisioning, a custom domain and an authenticated bootstrap before it can serve the browser application. Owner authentication accepts either configured Cloudflare Access or an Ed25519 owner assertion bound to the configured public key, host and email. A missing or invalid authentication configuration fails closed. The checked-in configuration targets only node.example.invalid; source configuration is not evidence of deployment. These files create no credentials.

The browser still runs the Cordis agent. The Worker supplies authenticated static assets, provider doors, selected-head compare-and-swap, organ-publication writer leases, presence and ordered private VFS persistence in dedicated Durable Objects. It does not run the agent while all tabs are closed. Durable Object storage is remote persistence, not an independent R2 backup.

Native shell and local-repository access, screenshots, Cloudflare deployment and runtime release recovery remain unavailable. Public HTTPS reads require the runtime network protection described below. The bounded cloud brokers do not fall back to a local machine. Provider turn IDs are durably single-use after dispatch; automatic retry and edge recovery are not implemented. Source capabilities do not create production credentials, configure bindings or establish a live deployment.

## Configure and verify

1. Approve the production authentication method for node.example.invalid. Cloudflare Access requires its actual team, audience and owner email. Ed25519 owner authentication requires a verified public key, exact host and owner email, plus a separately trusted way for the owner to obtain short-lived signed assertions. Do not copy an audience without verification, or treat the presence of a public key as approval to activate another access path.
2. Obtain required approval before configuring existing provider credentials for ongoing use by this new Worker. Provider doors remain 503 until their matching secret binding exists. Never place secret values in this repository, browser image or command transcript.
3. Build the actual browser preview through the repository's supported build. Inspect its VFS image and bundled build identity before uploading. Do not substitute the uncommitted local host or a static-only demo.
4. Set SOURCE_REVISION to the verified deployed browser source revision. Add only the new node.example.invalid custom-domain route after protection is ready. Deploy from this configuration.
5. Check unauthenticated refusal, owner login, initial boot, a real model reply, reload persistence, two-tab fencing, organ compile/apply/undo and actual remote acknowledgements. Check that other nodes you run remain unchanged.

The focused bootstrap suite runs with in-memory Durable Objects and synthetic mirror contents; it does not establish the deployed browser journey or Cloudflare resource behavior. Live acceptance requires the real main application after deployment security setup and memory transmission are authorized.

## Bootstrap driver

`node server/cloudflare-bootstrap-cli.mjs --dry-run` captures and validates the checkout's mirror without writes or network requests. `--mirror <directory>` selects another source; `--package <saved-directory>` inspects an existing package instead. Output contains only the seed ID, ball ID, epoch, batch counts and serialized byte sizes. A changing source, mismatched head copies, malformed module or excluded private path cannot be silently included as a successful seed.

`node server/cloudflare-bootstrap-cli.mjs --prepare --out <new-private-directory>` saves a validated package offline. The output directory must not exist and must be outside the source mirror. Preserve this directory unchanged: it contains the approved memory bytes and exact batch digests needed after an interrupted upload. It is private data, not a repository artifact. Preparation reads the same mirror as dry-run; neither mode reads credentials.

After the owner approves transmitting that exact package to Cloudflare, use `node server/cloudflare-bootstrap-cli.mjs --url https://node.example.invalid --package <saved-directory> --confirm-seed-id <seed-id> --access-token-stdin`. Supply an already authorized, unexpired RS256 Cloudflare Access JWT or EdDSA owner JWT on noninteractive standard input, never as a command argument, repository file or logged value. The CLI sends the token only as the `CF_Authorization` cookie to the fixed HTTPS bootstrap endpoint. It does not create, refresh or save credentials; the server verifies the token's issuer, audience, signature and owner. Authentication activation, assertion issuance and provider-secret provisioning remain separate operations. The CLI checks token structure and lifetime only; it does not establish the signer or owner.

Upload uses the saved package, not a fresh scan. It validates the complete package before transmission, then performs prepare, ordered batches and commit, checking matching HEAD and MIRROR acknowledgments. Existing unrelated state is refused. An incomplete run resumes only the same seed and acknowledged batch position. A timeout, malformed acknowledgment or lost response stops without automatic retry; keep the saved package and inspect the outcome before explicitly resuming. No overwrite, reset or rollback option exists.

`node --test server/cloudflare-bootstrap.test.mjs` exercises the driver and real Worker/DO handlers with isolated storage and synthetic home contents. The fixture reads the checkout's head and immutable module sources without executing those modules. It never seeds a live namespace, invokes a provider or alters the real mirror. This suite does not verify Cloudflare memory limits, the deployed assets or a closed-tab agent loop.

## Storage limits

Bootstrap and mirror uploads are capped at 34 MiB per request, with seed batches capped at 32 MiB of serialized entries. Ordinary Worker requests retain a 16 MiB ceiling. Mirror files are capped at 24 MiB (32 MiB once base64-encoded, so one such file plus its batch envelope fits a single request), with 20,000 retained VFS entries, 128 MiB decoded file state and 8 MiB path metadata. Each stored value is limited to 120 KiB, with file/conflict payloads split into 96 KiB chunks. A complete serialized snapshot is capped at 96 MiB; batches that would exceed that export budget fail before mutation. Snapshot reads validate metadata, chunk lengths and base64 padding and enforce the exact wire-byte count while streaming. Protocol replay acknowledgments retain up to the newest 64 per client and 4,096 globally across at most 256 clients. Global pressure may trim a client below 64; each client’s newest acknowledgment remains protected. Snapshot dumps under `/dsh/home/auma/snapshots/` (all but `LATEST.json`) are excluded from the cloud mirror, and the browser's cloud outbox drops them before sending. The browser's cloud outbox uses the same request, file and snapshot limits (`CLOUD_MIRROR_LIMITS` in `idb-persist.ts`, pinned by a parity test), and its local queue admits one 40 MiB batch. Historical memory versions are not implemented. Named runtime rollback snapshots are also not retained remotely: the runtime lists named files, while each boot replaces LATEST.json. Do not treat this mirror as historical snapshot recovery on a fresh browser. Current mirror source uses chunked content and streamed snapshots, but has not run on the actual Cloudflare runtime.

MirrorDO integrates `mirror-replay.mjs` pruning atomically with successful publication. Client sequence/digest fences and global lineage/revision remain permanent; content, tombstones, bootstrap state and user memory receipt journals are not compacted. A pruned retry returns HTTP 409 `MIRROR_REPLAY_EXPIRED` and attempts to retain a conflict; full conflict storage instead returns HTTP 507 `MIRROR_CONFLICT_CAPACITY_EXCEEDED` with `conflictCode: MIRROR_REPLAY_EXPIRED`. Neither result reapplies the batch or acknowledges delivery. Existing complete valid fenced inventories reduce on the next successful publication; malformed, incomplete or unfenced inventories fail closed. No standalone migration or production activation is implied.

## Deletion continuity

Snapshots expose `snapshotFormat: "x61-mirror-snapshot/v2"`, `resetPaths` and the surviving `entries`. Deletion and file/directory replacement atomically retain a subtree reset with the entry mutation, global revision and replay receipt. Resets survive later recreation; an ancestor reset subsumes child resets. Both resets and entries count against storage limits.

A reader requests `/api/snapshot?snapshotFormat=x61-mirror-snapshot/v2`, validates all paths, then durably clears permitted reset subtrees before overlaying surviving entries. It must refuse a reset that would erase local private identity, protected immutable modules or pending local work. Once resets exist, older readers receive `MIRROR_SNAPSHOT_UPGRADE_REQUIRED` rather than a snapshot that would resurrect packaged files. The browser hydration reader requests v2 and durably applies permitted subtree resets before surviving entries. Resets prevent future resurrection; they cannot reconstruct deletions discarded by an older deployment.

Cloud and local-host mirror admission reject secret path segments and their descendants, including `.ssh`, `.aws`, `.transport`, credential files, `.env*` and `.aukora-*`. Local snapshot walking applies the same exclusion before entering private directories. This is defense in depth; the browser must also exclude those paths before transmission.

The cloud mirror additionally excludes every exact `.conflict-backup` path segment and its descendants. Bootstrap scanning uses the same cloud policy without opening excluded directories. Local recovery backups and local-host transport remain unchanged. Existing cloud entries or reset records at excluded paths fail validation; they are not silently filtered or deleted. Preserve immutable queued batches and saved seed packages rather than rewriting their digests. Before deploying over existing state, follow the [cloud backup exclusion upgrade guide](../../docs/upgrade-guide/v0.2.2-alpha.2/cloud-conflict-backup-exclusion/guide.md) and obtain separate authorization for any required reconciliation.

## Owner-token browser login

An owner assertion is a compact EdDSA JWT signed outside the Worker by the holder of the configured Ed25519 private key. Its header contains only `alg: "EdDSA"` and `typ: "JWT"`; its claims contain only `iss: "aukora.x61.owner"`, `aud` equal to `PUBLIC_HOST`, `email` matching `OWNER_EMAIL`, and finite `nbf` and `exp` seconds. Both JSON objects use compact `JSON.stringify` encoding and canonical unpadded base64url. The current time must satisfy `nbf <= now < exp`; `exp - nbf` cannot exceed 24 hours, and longer tokens are refused. Shorter valid tokens remain accepted, without adding `sub`, `iat` or any new authority. Possession of this bearer token grants application access until expiry; it is not approval to sign an owner grant.

The [minter](../../server/mint-owner-jwt.mjs) accepts integer lifetimes of 1–24 hours and defaults to 24. This maximum and default of 24 hours (raised from 12) deliberately allows a stolen bearer token to remain usable longer. It does not renew or extend existing tokens. The [shared verifier](src/access.mjs) also applies the maximum to [explicitly configured local enrollment](../../server/local-enrollment.mjs), without changing local audience binding or enrollment authorization rules.

`POST /_auth/owner` accepts the raw JWT with `Content-Type: application/jwt`, exact same-origin `Origin` and `Sec-Fetch-Site: same-origin`. It verifies the token before issuing an HttpOnly, Secure, SameSite=Strict, host-only `CF_Authorization` cookie. Its lifetime is capped to the token's remaining validity, never extended by exchange. The posted JWT is the only login credential; existing cookies or headers cannot substitute for it, so a separately signed replacement can be exchanged without extending its expiry. The body is limited to 16 KiB and a ten-second read deadline. The endpoint can run before bootstrap, but does not serve the application or bypass bootstrap. Tokens are never returned in JSON or logged.

Unauthenticated HTML document requests to `/`, `/index.html` or `/preview.html` receive a self-contained sign-in page with HTTP 401. The request must be an exact `GET` without a query or fragment and explicitly accept `text/html` with positive quality; supplied fetch metadata must identify a document navigation. The page loads no application assets and uses `Cache-Control: no-store`, `nosniff` and a restrictive Content Security Policy. All other unauthenticated routes retain JSON refusals; host, authentication configuration and origin checks still fail closed.

The page submits an existing owner JWT only to `POST /_auth/owner`, clears the input before sending and on `pagehide`/`pageshow`, and permits one active attempt with a ten-second deadline. A successful exchange replaces the page with `/`; interrupted or stale attempts cannot navigate. This is a sign-in interface and cookie exchange, not a token issuer, key-provisioning service or renewal service. A new computer still needs a trusted way to obtain an authorized assertion. Do not load the owner's private signing key into the browser application, its VFS, a model prompt or this repository. Activation of this access method is a separate production security change; source and isolated tests do not verify deployment or a live owner login.

## Edge Aura evidence

The Head Durable Object reads current Aura inputs through its bound Mirror Durable Object. The internal `/_mirror/aura-inputs` route requires internal authorization and a matching completed bootstrap identity; the public Worker does not forward this route. The reader checks bounded receipt, DAG, handoff, discovery and assignment evidence, and returns aggregate metrics rather than raw private files. Head identity and mirror revision checks reject changes across awaited reads. Missing, corrupt, oversized, timed-out or inconsistent inputs stay incomplete with a null vector.

Wake alarms can compute and retain these peripheral attention hints without a local machine or browser tab. Model-backed wake execution requires the exact setting `WAKE_EXECUTOR_ENABLED=1`, a configured provider and its existing budgets; credentials alone do not enable it. With `0`, an absent setting or any other value, neither scheduled/manual probes nor direct `wish_step` calls execute the cloud step, reserve budgets or write execution state. Wake scheduling, receipts and peripheral hints remain available. Enabled manifest entries describe selection, not observed organ health; wake execution does not confer approval authority.

## Deterministic facts

The source routes authenticated, bodyless `GET /__x6/facts` and `GET /api/x61/facts` requests through completed bootstrap to Head and its bound Mirror. Queries and fragments are rejected. The response projects a fresh, coherent snapshot: selected head identity, declared/enabled organ counts, verified receipt totals and counts by kind, checkpoint coverage, DAG counts and Aura attention metrics. It does not call a model, expose raw memory or credentials, or mutate state.

Receipt hashes and chains, checkpoint signatures and covered receipt prefixes are verified before complete counts are returned. Checkpoint signer trust is explicitly unpinned: a valid signature is neither owner approval nor an independent audit. Organ selection is not runtime health. Missing, corrupt, inconsistent or unavailable evidence returns HTTP 503 with incomplete status and null counts, not synthetic healthy zeroes. Responses use `Cache-Control: no-store`. Source handlers and isolated tests are not evidence that either endpoint is deployed or live.

AUMLOK facts accept legacy invite counts and the bounded `lifetimeIssuedCount` field without exposing extra identity data. Lifetime totals must cover monthly issuance and revocations, stay at most 128, and be zero while unbound. Invite listing and redemption are edge-only: the local host returns `501 AUMLOK_EDGE_ONLY_ROUTE` before passkey handling. Both status aliases (`/__x6/status` and `/api/x61/status`) identify their runtime as `cloudflare` or `local`; this field does not establish health.

## Authentication and bounded reads

Public application routes, including mirror mutations, snapshot reads and static assets, require a valid owner assertion. Cloudflare Access assertions use RS256 and the configured issuer and audience. Ed25519 owner assertions use EdDSA and the configured public key, exact public host and owner email. Missing configuration fails closed. On ordinary application routes, multiple assertion headers and the authorization cookie must agree; distinct Cloudflare Access and owner tokens are rejected rather than selected by precedence. Choose the configured login path consistently. The Worker strips caller-supplied internal authorization markers before forwarding authenticated requests to its Durable Objects. Neither a local-host capability cookie nor a mirror bearer token bypasses authentication. Ordered writes use `/_mirror/delta`; legacy `/_mirror/push` is unsupported. Status routes are `/api/health`, `/_mirror/status` and `/_head/ball`.

The browser retains one deadline through headers and the complete response body: 8 seconds for hydration and 15 seconds for delivery. Successful snapshots are limited to 96 MiB; acknowledgments and errors to 64 KiB. Byte limits are enforced on streamed decoded bytes, malformed UTF-8 is rejected, and identity-encoded Content-Length must match. A failed or truncated response cannot acknowledge or remove its queued batch. Snapshot resets cannot select protected roots or immutable ball storage.

## Cloud capability inspection

Owner-authenticated `GET /_host/selftest` and `POST /_host/repo` with `action: selftest` require completed, matching HEAD/MIRROR bootstrap and `Sec-Fetch-Site: same-origin`. Only the selftest GET may omit `Origin`; a supplied `Origin` must match, and a supplied `Referer` must be same-origin without URL credentials. The POST retains the exact-origin requirement.

The bounded read-only report observes HEAD, MIRROR, AUMLOK single-credential binding status and build metadata. Provider configuration presence is under `providerDoors`; broker flags are under `brokers.githubConfigured`, `brokers.cloudflareConfigured`, `brokers.webEyesConfigured` and `brokers.trustedDocsConfigured`. It sends no provider request and performs no publication. Missing or invalid observations remain unavailable or invalid; even `ok: true` does not prove credential validity, model availability, runtime health or successful deployment.

Bootstrap HEAD/MIRROR reads have separate 60-second deadlines. Subsequent broker request-body reading and each selftest projection have separate ten-second deadlines. These staged limits are not a ten-second end-to-end deadline.

## Bounded edge diagnostics

Owner-authenticated, bodyless `GET /_host/diagnostics` and `POST /_host/repo` with exactly `{"action":"diagnostics"}` require completed paired bootstrap and `Sec-Fetch-Site: same-origin`. The POST requires exact `Origin`. The GET may omit `Origin`; a supplied value must match, and any `Referer` must be same-origin without URL credentials. Queries and fragments are refused.

The response separates `worker`, `head` and `mirror`. Each available scope retains at most 100 handled requests within 32 KiB, ordered by response readiness. Events contain start time `at` in epoch milliseconds, a bounded `method`, canonical `pathname`, HTTP `status`, fixed `HTTP_<status>` `code` and `durationMs` capped at 24 hours. Status and duration stop when the handler returns a Response or throws; thrown handlers record synthetic HTTP 500. Later SSE or snapshot stream errors, transfer failures and WebSocket traffic are invisible. Mirror duration includes queue wait. Provider paths become `/door/:provider`; unknown paths become `/:other`. The observer stores no bodies, queries, headers, credentials or raw error text. Codes report HTTP status, not application error details.

Histories belong to one Worker isolate or Durable Object instance, disappear on restart and omit their own in-flight retrieval. They are not a global durable audit, browser network capture or evidence of deployment. Unavailable or invalid components return `state: unavailable` with `DIAGNOSTICS_UNAVAILABLE`; the report retains available components and returns HTTP 503 with `DIAGNOSTICS_INCOMPLETE` rather than inventing events. See [the metadata-only recorder](src/edge-diagnostics.mjs).

## Repository and GitHub brokers

`/_host/repo` and `/_host/github` require owner authentication, exact same-origin requests and completed paired bootstrap. GitHub operations are fixed to `your_org_x/your-node`; source publication targets `main`. Repository `read`, `tree` and `diff` cover admitted source paths beyond seed organs; live MIRROR reads retain their independent, narrower path policy. Private memory is not a GitHub fallback or publication source. Path and content checks conservatively refuse private or secret-like data and can reject legitimate source files. Publication filenames and content are screened before approval or network calls; complete serialized broker results are also screened. See [the broker](src/cloud-brokers.mjs) for admitted paths and request fields.

The repository is the node's own. `sync_head_to_github` commits this node's head, its organ modules, `mirror/home/auma/HANDOFF.md` and the receipts ledger to `main` of that repository in one commit, so set the repository to the node's own private repository and never to the shared source repository. Two things fail closed: the placeholder owner `your_org_x` cannot exist on GitHub (a login has no underscore), so an unedited node reaches no repository; and the edge refuses a head sync with `HEAD_SYNC_SHARED_REPOSITORY` when the configured repository is the shared `aukora-x7`.

Source reads and diffs resolve immutable commit SHAs and validate Git tree modes, ancestor directories and regular-file entries. Historical commit metadata and diff bases require a bounded ancestry comparison against pinned `main`; diff heads cannot be caller-selected SHAs. Reads are capped at 256 KiB decoded. Tree results expose `treeSha`, filtering and truncation flags, and return at most 1,000 entries within a 96 KiB projected-entry budget from one bounded recursive response, not a complete inventory guarantee. GitHub issue, pull-request, comment and workflow reads use bounded pages; `moreMayExist` and diff/tree truncation must be preserved. These brokers do not silently exhaust pagination or follow arbitrary refs, symlinks or submodules.

Repository `write`, `commit` and `push` publish explicit source payloads with an expected-head comparison. Each publication needs exact, single-use Class 3 approval through the owner's Touch ID/passkey flow, bound to the destination and complete request content. GitHub `action: api`, `method: POST` permits only issue creation at `/repos/your_org_x/your-node/issues` with `title` and `body`, or a comment at `/repos/your_org_x/your-node/issues/N/comments` with `body`, under the same approval requirement. Comment creation verifies that `N` is an issue and refuses PR numbers. A login or configured GitHub token does not grant publication consent; source publication neither selects the running HEAD nor deploys it.

Never automatically retry an uncertain external mutation. Source post-dispatch failures, including output-screening failures, return HTTP 503 with `REPO_PUBLICATION_OUTCOME_UNKNOWN`, `outcome: unknown`, `retry: repeat-the-identical-request-to-reconcile` and `requiresFreshClass3Approval: true`. This hint permits deliberate reconciliation with a newly approved identical request, not automatic resubmission. Absence of a marker in bounded commit history is not proof of nonexecution.

Issue/comment post-dispatch failures return HTTP 503 with `GITHUB_MUTATION_OUTCOME_UNKNOWN`, `outcome: unknown`, `retry: inspect-github-before-new-approval`, `requiresFreshClass3Approval: true` and `replaySafe: false`. They have no idempotency guarantee. Inspect GitHub before requesting fresh approval or submitting anything again.

## Source bytes and state comparison

`POST /_host/repo` with `action: bytes` accepts `path` and optional `offset` and `length`, defaulting to 0 and 256 bytes. Slices are capped at 4,096 bytes from files no larger than 256 KiB. This action reads only the admitted remote-source subset at pinned GitHub `main`, never live MIRROR or private memory. It screens the complete UTF-8 file for secrets and invalid control bytes and verifies its Git blob hash before returning any bytes or digest. Results include the pinned `commitSha`, `blobSha`, total size, actual slice length, integer `bytes`, `hex` and whole-file `sha256` with `hashScope: whole-file-original-bytes`. Original bytes, including a UTF-8 BOM, are preserved. An offset at EOF returns an empty slice; an offset beyond EOF is refused.

The same endpoint with `action: state_diff` accepts an optional complete `base` containing `head: {ballId, epoch}` and `mirror: {lineageId, revision}`. HEAD compares retained, validated manifests within one storage transaction. Retention does not prove the caller's baseline was previously selected, is an ancestor of current HEAD or belongs to an attested lineage. Each manifest is capped at 256 KiB and 256 entries; the response exposes at most 100 changed entry IDs with `added`, `removed` or `modified` status, plus `total` and `truncated`. It returns no module bodies, configuration values or file contents. MIRROR compares only its current lineage/revision against the caller-supplied fence; that fence does not attest historical content. The combined report explicitly sets `atomicAcrossBindings: false` because HEAD and MIRROR observations are separate.

Without a baseline, `basis: snapshot-only` returns current identities with null change indicators and unavailable entry comparison, not zero changes. A requested comparison lacking retained basis or metadata returns HTTP 503 with `STATE_DIFF_INCOMPLETE` and preserves available observations; unavailable entry comparisons have null changes and counts. Malformed baselines return HTTP 400; a retained HEAD epoch mismatch or a future revision in the current MIRROR lineage returns HTTP 409. These reads retain the existing authentication, same-origin and bootstrap checks and do not authorize publication or promotion. See [the bounded state projection](src/state-diff.mjs).

## Public HTTPS reads

Owner-authenticated, same-origin `POST /_host/web-eyes` with `action: fetch` and `url` selects general public HTTPS reads only when the actual Cloudflare runtime reports both `global_fetch_strictly_public` and `no_cots_on_external_fetch` as true. The adapter captures global fetch and relies on Cloudflare production's post-DNS public-address enforcement and default external TLS trust, not application IP pinning or a DNS preflight. Local Miniflare networking does not establish that guarantee. Source and synthetic checks do not establish production activation.

The [production launcher](../../server/deploy-cloudflare.mjs) prints its fixed plan by default or with `--print`, without starting a subprocess, building, uploading or deploying. Only explicit `--deploy` starts pinned Wrangler 4.159.0 with both compatibility flags; production deployment still requires separate authorization. A fixed empty `--env-file` intentionally prevents loading project `.env` files. The canonical Wrangler configuration omits these flags for local development. Runtime flags are not production attestation: forcing them into local emulation is unsupported and does not provide the production public-address guarantee.

General reads accept public DNS hostnames and nonsecret queries, while refusing literal IPs, local or metadata hostnames, nonstandard ports, the deployment's own host, URL credentials and fragments. Requests use anonymous GET with fixed headers, no caller authentication, redirects or automatic retries. Responses must be complete UTF-8 HTML, plain text, JSON or XHTML without compression or NUL bytes. The complete body and broker JSON result are each capped at 256 KiB, so envelope overhead reduces the effective content limit. A ten-second transport deadline includes headers and body.

Without those runtime flags, the distinct `trustedDocsHttpsFetch` fallback retains exactly `https://api.github.com`, `https://developers.cloudflare.com`, `https://developer.mozilla.org` and `https://registry.npmjs.org`, with only numeric GitHub `page` and `per_page` queries. It trusts those providers' DNS and platform TLS and does not promise general public-address enforcement. Results identify `capability: public-web-fetch` with `networkPolicy: cloudflare-global-fetch-strictly-public`, or `capability: trusted-docs-fetch` with `networkPolicy: trusted-origin-allowlist`. Health reports expose `capabilities.publicWebFetch` and `capabilities.publicWebNetworkPolicy`; selftest exposes `brokers.webEyesConfigured`.

The broker screens raw, decoded and canonical outbound URLs, returned text and the complete serialized result for recognized secrets and configured credential values; authentication-like query keys are refused. These checks are defense in depth, not a universal privacy guarantee for caller-selected paths or content. Read access does not authorize uploads, external writes, credential disclosure or deployment. See [the transport](src/public-https-transport.mjs) for both policies.

## Deployment, archive reporting and recovery limits

The deploy workflow keeps source, authority, build, artifact and bundle gates mandatory. Missing `CLOUDFLARE_API_TOKEN` or `CLOUDFLARE_ACCOUNT_ID` repository secrets skip publication with an explicit step summary, not a deployment claim. The observer runs only after Wrangler reports successful publication. Configured deployment, stale-main and gate failures remain fatal.

Owner-authenticated `GET /_host/estate` and `POST /_host/estate` with `{ "action": "archive_status" }` read at most 64 object metadata rows for each fixed `snapshots/`, `modules/` and `files/` prefix. Per-prefix counts and byte sums cover only the observed page; truncation and omitted names remain explicit. `prefixSummaryComplete` covers those three fixed prefixes only; the existing top-level `truncated` and `omittedObjectCount` fields describe snapshots only. Responses disclose no content keys or snapshot payloads. `backupStatus` distinguishes `unconfigured`, `empty`, `no-latest-pointer` and `snapshot-present`; `integrityVerified` stays false because metadata presence is not a restore drill. The estate GET also compares the observed latest snapshot's epoch and ball ID with selected HEAD in `latestMatchesSelectedHead`. These observations do not establish an atomic snapshot across independent stores.

`POST /_host/aumlok/redeem` remains authenticated code verification only: the request is a signed invite receipt plus its 32-byte base64url code. Seven words are the owner's local recovery secret, not an invitation code, and must never be submitted. A verified code grants no cookie, session, enrollment, consumption or Class 3 authority; `guestAccess` explicitly reports `GUEST_ACCESS_UNAVAILABLE`. Guest sessions require a separate issuer, isolated resources and capability routing before access can be enabled.

Whole-store restore still has ten open acceptance requirements. Its isolated real-store tests demonstrate whole-store replay despite a surviving external observer, consumed-approval resurrection after identity-row rollback and expired-approval resurrection after clock rollback. These are gap reproductions, not passing restore acceptance. Independent admission witnesses, owner recovery epochs, durable clock/node checks and runtime ancestry adapters are still required.

## Voice bridge, provider turns, gates and signed actions

The raw PersonaPlex WebSocket bridge now fails closed with `VOICE_RENDERER_PROTOCOL_UNSUPPORTED`, even when its URL is configured. The current renderer provides no verified frame protocol for enforcing a journaled session, state slot, clause queue or idle directive. Keep voice controls unavailable while `bridgeAvailable` is false. Clause validation is a targeted deny-list, not a guarantee that arbitrary text contains no secrets. State slots truncate only at UTF-8 code-point boundaries.

Provider HTTP requests now execute in HeadDO after exact durable turn-journal admission. Barge-in, abandonment, replacement and request cancellation abort the owning upstream controller through stream completion. Dispatched and cancelled turn IDs cannot be retried, including after the 256-row journal window evicts their text. Index tombstones remain durable; no automatic pruning or retry is provided. A transport failure after dispatch remains an unknown outcome. Create a fresh turn only for an independently intended operation, never to retry an uncertain side effect.

Owner login, AUMLOK bind/approve and protected promotion gates preserve their original failure status for the first four failed attempts within one minute and return `429 GATE_LOCKOUT_ACTIVE` on the fifth. The five-minute lock survives object recreation. Login buckets use hashed Cloudflare caller IPs; missing IPs share a fallback bucket. Head gates use the authenticated subject and operation, serialize side effects, and share the promotion bucket with direct ball publication carrying a Class 3 token. Success resets unlocked failures. No signing credential or passkey requirement is weakened.

Staging a different candidate on the same parent and epoch requires explicit `replaceStaged: true`; identical staging preserves `stagedAt`. Publication checks the active candidate within its transaction, including after a promotion captured an earlier candidate. Publish outcomes persist across object recreation. Aura exposes `handOffEpochMismatch` only when complete evidence supplies a boolean.

Optional `x-x6-signed-action` JSON or top-level `body.signedAction` envelopes are verified on stage, promote and ball publication; supplying both is refused. The hybrid payload uses `head.stage`, `head.promote` or `head.publish`, the current parent HEAD `ballId` and `epoch`, and the exact request origin as `audience`. Its `targetDigest` is SHA-256 of canonical JSON `{ method, pathname, body }`, where `body` is the complete HTTP JSON body with only top-level `signedAction` removed. Thus lease fields and explicit staging replacement are signed when present. The independently provisioned owner Ed25519/ML-DSA keys authenticate the envelope. A signed action never substitutes for session or Class 3 WebAuthn approval. Its durable single-use key commits atomically with a successful stage/publication; failed validation does not consume it.
