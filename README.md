# Aukora

English | [中文](README.zh.md)

Aukora is a personal AI node that one person owns. Its AI, Auma, is built from small replaceable modules called organs, and she can write, compile, test and stage the next version of herself. What proposes never permits: a change to her own judges, a merge into her repository or a post to GitHub waits until the owner approves those exact bytes with a passkey, and the edge, not Auma, makes that check.

The edge is a Cloudflare Worker with two Durable Objects (its storage). The agent runs in the owner's browser, on the inherited DeepSeek Harness runtime that makes up most of `packages/`; Aukora's own layer is the authority, self-change and recovery code named below. This tree is a prototype, exported by script from a running private node without that node's world (its data, keys, names and history). Every node starts at the same genesis head.

Where the weight is, by file:

- **An approval covers exact bytes and is spent once.** The edge ties each passkey challenge to the origin, method, path and body hash of one request, and spends the approval in the storage transaction that reserves that body hash. `deploy/cloudflare/src/aumlok.mjs`, `deploy/cloudflare/src/head-do.mjs`.
- **One rule decides what counts as a failed proof, and a test reads the source to hold it.** Only a proof that was checked and was wrong can move a lockout. A 1,091-line test parses the owner-identity source, follows aliases, and fails if a verifier is called anywhere else; its exemption list is empty. `deploy/cloudflare/src/proof-failure-rule.mjs`.
- **She compiles candidates of herself, and the parent grades them again.** A candidate organ is compiled in a separate worker and run against a retention suite. A pass that the candidate reports for itself is ignored. `packages/experimental/webworker-runtime/src/x6/scion.ts`, `mirror/home/auma/seed/organs/seed-pearl.js`.
- **Identity, keys and judges sit in 25 sealed Wasm cells.** Each is pinned by size and SHA-256 (checkable without running anything), has zero imports, and runs on a fuel grant in a worker that is ended after 5 seconds. `packages/experimental/webworker-runtime/src/x6/wasm-cells.ts`.
- **The owner has a way back in.** A rescue page, a vault, a bounded archive, and a restore that writes only into an empty edge. `deploy/cloudflare/src/rescue-kit.mjs`, `deploy/cloudflare/src/recovery-restore.mjs`.

Counted in this tree: 26 organs in the genesis head, 25 Wasm cells with 169 named operations, 26 agent tools, 15 governance ids that only the owner's passkey can change, 48 edge modules of more than 22,000 lines with 71 test files, 152 spec files for the app and the browser runtime, and more than 3,500 test cases written.

Status: the tests are in the tree to be run. Some are known red, each listed with its count and reason in [docs/KNOWN-RED-TESTS.md](docs/KNOWN-RED-TESTS.md). One run of this tree as shipped, by its authors on one machine, is recorded in [docs/RUN-RECORD.md](docs/RUN-RECORD.md): an offline install, the build, a boot of the local host and 5,502 test cases, of which 90 failed: 89 known red and 1 found by that run and still red. That run found one more failure, made by this repository's export; the export was corrected and that suite, run again, had no failure. It shows no deployed node and no browser session, so run it before you rely on it. Labels below: RAN (done in that recorded run), SOURCE (read in code, with its path), UNVERIFIED (not checked here), DIRECTION (an aim).

### Authority: AUMLOK and the owner's passkey

Code is in `deploy/cloudflare/src/` and tests in `deploy/cloudflare/src/__tests__/` unless a longer path is given.

- **Exact bytes, spent once.** The passkey signs a random challenge, and the edge holds that challenge bound to the origin, method, path and body hash of one request (`aumlokClass3Binding` in `aumlok.mjs`), so the approval is spent only on those bytes. It lives five minutes and is spent once. For her GitHub posts, `consumeClass3` in `head-do.mjs` spends the approval and reserves the body hash in one storage transaction. The reservation is never released automatically, also when the outcome is unknown, so a reload cannot post twice. The ledger holds 4,096 reservations and then refuses. Tests: `convergence-approval-fencing.test.mjs` (5 cases), `cloud-brokers.test.mjs` (29 cases).
- **The page asks for the bytes it showed.** For a staged GitHub post the page reads the request strictly, shows its full text, reads the file again at the click, and asks the passkey only if it is still the same request. `packages/client/ui-layout/src/client/spatial/aumlok/outward-class3.ts`.
- **Sign-in with the bound passkey, behind a gate.** A session lasts 8 hours at most and is not an approval. Five wrongly signed passes within 60 seconds lock the door for 300 seconds. One case sends 100 overlapping wrong passes and asserts that at most five signature checks start. `aumlok.mjs`, `gate-lockout.mjs`, `owner-login-slots.mjs`. Tests: `owner-passkey-signin.test.mjs` (31 cases), `owner-login-gate.test.mjs` (14 cases).
- **One rule for a failed proof, made structural.** A lockout counter moves only when a cryptographic proof was checked and was wrong. Junk, an expired challenge or a library error never counts, so an outsider cannot lock the owner out. In `proof-failure-rule.mjs` only `proofOutcome` calls a verifier and only `countFailure` moves a counter, and an outcome carries a private brand that no other module can make. A passkey answer is screened first by the project's own parse (`webauthn-screen.mjs`), and a mismatch there is refused uncounted. `proof-failure-rule.test.mjs` (11 cases, 1,091 lines) parses the owner-identity source with the TypeScript parser, follows renamed and namespace imports, aliases, destructuring and `bind`, and fails if a verifier is called or a counter written anywhere else. One case makes every edge file that calls a verifier be listed as identity code or as not, with a reason, and the list of open exceptions (`OPEN`) is empty. Six of its cases plant a known way around the rule, such as a renamed, destructured or bound verifier or a counter written through `Reflect`, and assert that the scan catches each one.
- **A second device's passkey.** An enrolled passkey approves "add a device" and gets a one-time code: 256 random bits, stored only as hashes, ten minutes, burned after five wrong tries. The new computer registers a passkey but only joins. It cannot sign in until an enrolled passkey confirms the exact key, shown as a six-digit phrase. `passkey-devices.mjs`. Test: `passkey-devices.test.mjs` (69 cases).
- **The seven words.** The page draws seven words with `crypto.getRandomValues`, uniformly over 11,253,636,424,086 valid phrases (43.36 bits), and shows them once. The commitment it keeps is PBKDF2-SHA256 at 600,000 iterations, salted with the node's public key. The file header gives the reason for both choices. `packages/client/ui-layout/src/client/spatial/aumlok/aumlok-ceremony.ts`. The words seal a 32-byte root with AES-256-GCM. The node's Ed25519 key is derived from that root, and the sealed root is released only after the bound passkey asserts. `packages/client/ui-layout/src/client/spatial/aumlok/aumlok-root.ts`.
- **The night grant.** One passkey tap lets her add or replace ordinary organs alone, within 12 hours, 12 uses and 8 organs per use. Governance ids are never covered. `night-grant.mjs`, `night-grant.test.mjs` (21 cases).
- **She cannot change her own judges.** Fifteen ids are owner-only by name, and so is any entry that declares itself governance. Ten are organs: receipts, Pearl, Aura, prediction, recall, memory, the body map, the superagent, the scion and boot. Five are Wasm cells: two judges, the grant ledger, identity and keys. A change to any of them needs the passkey on the exact candidate bytes. An owner grant must carry an Ed25519 and an ML-DSA-65 signature. `server/ball-transition.mjs`, `deploy/cloudflare/src/owner-grant-policy.mjs`, `packages/client/ui-layout/src/client/spatial/aumlok/head-promotion.ts`. Tests: `deploy/ci/authority-preflight.test.mjs` (10 cases), `hybrid-envelope.test.mjs` (6 cases).

### The organism: organs, balls, the scion and Pearl

Organs are in `mirror/home/auma/seed/organs/`. Runtime code is in `packages/experimental/webworker-runtime/src/x6/` and its tests in `packages/experimental/webworker-runtime/tests/x6/`.

- **The genesis head.** Every node starts from the same head: epoch 1, no parent, 26 entries, author `genesis` (`mirror/home/balls/HEAD.json`), with the Pearl suite and six scars. What a node grows after that is its world, which `.gitignore` keeps out of the repository.
- **Balls and epochs.** A ball is a manifest that lists every organ by the SHA-256 of its code, and its id is its own hash. A new head must name the current ball as parent and be exactly one epoch higher. A stale caller gets `REBASE_REQUIRED`. `server/ball-head.mjs`, `deploy/cloudflare/src/head-do.mjs`. Test: `server/ball-manifest.test.mjs` (6 cases).
- **She stages her own next version.** Three tools stage it for the owner. `stage_organ_promotion` changes one organ, and `stage_organ_set_promotion` adds one to eight ordinary organs. Each clones the live head, adds one epoch and posts the candidate to `/_head/stage`. `stage_head_promotion` writes one governance candidate to a review file for the owner. None of them publishes or approves. `ball-loader.ts`. Test: `stage-organ-promotion.spec.ts` (10 cases).
- **Live self-change with an undo.** `tree_patch` mounts or hot-swaps one organ in the running agent without a page reload, and a failed activation is rolled back. `tree_undo` returns an organ to its previous version and disposes what it had registered, last first. `self_apply` stores new code and swaps it in as one step, and `self_undo` reverts the last change. `ball-loader.ts`.
- **The scion and one self-build step.** `scion.ts` takes up to 128 source files and 2 MiB and compiles them with a pinned offline esbuild-wasm in a separate worker. Compiling does not run or select the result. `seed-cycle.js` then writes the organ, hashes it, installs it, runs its acceptance cases, and keeps it or undoes it. The `scion_grow` tool joins the two (`scion-growth.ts`).
- **Pearl, and tests that attack the judge.** A retention suite of 17 cases and six scars ship as seed files (`mirror/home/auma/seed/pearl/retention-suite.v1.json`, `mirror/home/auma/seed/scars.jsonl`). Each scar records a failure and its lesson. Five of the six name the checks that now guard them, 14 in all, and every one of the 14 is a case of the suite. `scar-aura-silent-calm` names none yet. `seed-pearl.js` runs two builds of an organ against the whole suite in a disposable trial worker. In `scion-growth.spec.ts` (27 cases, one on the known-red list) a candidate tries to post a forged pass, and the parent ignores worker pass flags and grades the outputs again. Also `server/pearl.test.mjs` (38 cases).
- **Receipts, predictions and Aura.** `seed-receipts.js` keeps a hash-chained receipt log with Ed25519-signed checkpoints. `seed-predict.js` seals a prediction about the next promotion as a receipt before anything changes, and stores no score: readers recompute surprise from the chain. `seed-aura.js` computes her coherence by fixed rules, and its authority tier is always `peripheral-hint`. Tests: `server/aura.test.mjs` (16 cases), `server/receipts.test.mjs` (10 cases, 6 on the known-red list).
- **25 sealed Wasm cells.** Each file in `apps/web/public/cells/` is pinned by size, SHA-256 and a fuel grant in `wasm-cells.ts`. The loader admits a cell in a fixed order and stops at the first failure: the size, the hash on a private copy, then the memory limits read from the binary (one unshared 32-bit memory with a declared maximum), all before it compiles. Then it requires zero imports and exactly the metered export set. Every call runs on a fresh fuel grant in a separate worker that is ended after 5,000 ms, and the live memory is checked again after every call. The cells hold identity, keys, four judges, the grant ledger, risk, memory policy, Nostr signing and encryption, and layout. She calls them with the `x6_cell` tool. One cell, skillsmith, compiles WAT text into a new metered cell: `aura-focus.wasm` is built that way from `aura-focus.wat`, and `server/aura-focus-cell.build.mjs` exits 1 if the checked-in bytes differ. Test: `wasm-cells.spec.ts` (13 cases).
- **26 tools.** Besides staging and self-change, the loader registers tools for self-inspection (`x6_capability_index`, `x6_browser_estate`, `auma_snapshot`), outward reach through host-held doors (`x6_repo`, `x6_github`, `x6_cloudflare`, `x6_web_eyes`), advice from up to six other models at once (`x6_consult`), up to six parallel subagent tasks (`x6_swarm`), durable wishes with an acceptance and a step limit (`x6_wish`) and her Nostr identity (`x6_nostr`). `ball-loader.ts`. Test: `capability-index.spec.ts` (6 cases).
- **Waking with no tab open.** A Durable Object alarm can wake her for a bounded session: 3 rounds, 6 tool calls, 15 seconds (`CLOUD_WAKE_LIMITS` in `deploy/cloudflare/src/head-do.mjs`). `deploy/cloudflare/src/cloud-wake-tools.mjs` adds three read-only repository tools and one model turn through `deploy/cloudflare/src/cloud-model-door.mjs`, and itself writes, stages, promotes, approves and publishes nothing. The wake runs a model only under the exact setting `WAKE_EXECUTOR_ENABLED=1` (`deploy/cloudflare/README.md`). Tests in `deploy/cloudflare/src/__tests__/`: `cloud-wake-bounds.test.mjs` (23 cases), `cloud-wake-off-switch.test.mjs` (5 cases). The open-tab side is `wake-loop.spec.ts` (11 cases).

### The edge: one Worker, HEAD and MIRROR

Code is in `deploy/cloudflare/src/` and tests in `deploy/cloudflare/src/__tests__/` unless a longer path is given.

- **One Worker, two Durable Objects.** `worker.mjs` (2,105 lines) checks who is calling and routes. HEAD (`head-do.mjs`, 2,808 lines) holds which ball is selected and the login lockout. MIRROR (`mirror-do.mjs`) stores a copy of her home as ordered updates and refuses secret-shaped file names. Tests: `head-hardening.test.mjs` (20 cases), `worker.spec.ts` (96 cases as written, 98 when run, since some are made in a loop; 5 are on the known-red list).
- **The rescue page and the vault.** `/rescue` copies what one browser holds of Auma without starting her app and without writing to that browser. It sends the copy to the vault, as pieces named by their SHA-256, or saves one pack file that `server/rescue-verify.mjs` re-hashes. `rescue-kit.mjs`, `rescue-page.mjs`, `vault.mjs`, `world-budget.mjs`. Tests: `rescue-pack.test.mjs` (22 cases), `rescue-page.test.mjs` (31 cases).
- **The bounded archive, and restore into an empty edge only.** `cold-archive.mjs` (2,055 lines) writes the edge state as a content-addressed archive bound to the owner, with a rebuild drill that runs under its own object names. `recovery-restore.mjs` writes only into an edge with no HEAD and no mirror. A live edge is only compared. Tests: `cold-archive-bounded.test.mjs` (44 cases), `recovery-restore.test.mjs` (34 cases).
- **Model doors, and a journal written before the call.** Model calls go to `/door/<provider>/` on the same origin through seven doors for six providers: `deepseek`, `moonshot` (two doors), `openrouter`, `openai`, `anthropic` and `xai` (`packages/experimental/webworker-runtime/src/model-doors.ts`). A door lets the host add a key that only it holds. `turn-journal.mjs` commits the turn and the SHA-256 of the request to storage before the provider is called, so a crashed tab does not lose what was asked. When a call fails after dispatch, `provider-dispatch.mjs` answers `PROVIDER_OUTCOME_UNKNOWN` with `do-not-repeat-automatically`. Tests: `provider-dispatch.test.mjs` (17 cases), `turn-journal-and-body.test.mjs` (5 cases).
- **Brokers for outward work.** Through `/_host/repo` she reads the repository and works on branches named `auma/proposal/<name>`. Publication needs a passkey approval, and an unknown outcome is answered as unknown. `cloud-brokers.mjs`. Test: `repo-brokers.test.mjs` (43 cases).
- **Deploy gates.** `deploy/ci/` holds a scrub gate that scans source and built bundles, the authority preflight, a rule for what a head sync may commit, and a test that pins where the production credential may appear in the workflows. Nine test files, among them `deploy/ci/scrub-gate.test.mjs` (25 cases).
- **A signed head announcement, and a local host.** `nostr-anchor.mjs` publishes one Nostr event of kind 30078, signed by the node key, that says which ball and epoch is her head. The file says it is not a relay. `server/local-host.mjs` emulates HEAD and the mirror on one machine, and the dry run of `server/cloudflare-bootstrap-cli.mjs` never writes or connects. Tests: `nostr-anchor-door.test.mjs` (26 cases), `server/cloudflare-bootstrap.test.mjs` (13 cases).

## Check it yourself

Nothing in this file asks to be taken on trust. It was written so that a person, or an AI reading for one, can check each line.

- **Pick any line of "What is built".** Open the path and read its header comment. Then open the test named beside it and read what it asserts.
- **Count again.** Run the counting commands in "The numbers". A count that differs is a fault in this file.
- **Run the tests.** The commands are in "Run it". Compare any failure with [docs/KNOWN-RED-TESTS.md](docs/KNOWN-RED-TESTS.md). A failure that is not on that list is news.
- **What the tree shows, and what it cannot.** It shows the code and the tests as written, and one run by its authors on one machine ([docs/RUN-RECORD.md](docs/RUN-RECORD.md)). That is a record, not a guarantee: a pass on your machine, a deployed node, a browser session or a speed is yours to measure.
- **What is inherited.** Most of `packages/` is the inherited DeepSeek Harness, built on Cordis, which is vendored in `vendor/`. Aukora's own code is mainly in `deploy/`, `server/`, `mirror/`, `apps/web/public/` and the `packages/` paths named above.
- **Where the passkey rule stops.** The passkey is asked for the actions named here. A change to one ordinary organ needs a signed owner session, not a passkey (`server/ball-transition.mjs`). A hash chain is not an approval: `docs/START-HERE.md` states that a checkpoint is not a passkey.

## The names, in plain words

[docs/GLOSSARY.md](docs/GLOSSARY.md) defines ball, organ, epoch, receipt, checkpoint, head and the rest of the mechanics. The project names are explained here.

- **Auma**: the AI that lives on a node. **Organs**: her modules, each one a Cordis plugin (Cordis is the plugin framework in `vendor/`). **Ball**: a content-addressed bundle of modules, versioned by an integer, the epoch. **HEAD** and **MIRROR**: the two Durable Objects of the edge. HEAD selects the ball, MIRROR holds her home.
- **AUMLOK**: the identity door: passkey enrolment, owner sign-in, devices, the seven words, invites and exact-bytes approval (`deploy/cloudflare/src/aumlok.mjs`).
- **Aura**: her coherence reading (`mirror/home/auma/seed/organs/seed-aura.js`). The Aura Coherence screen draws every health cell as Undetermined until a host feeds it (`packages/client/ui-layout/src/client/spatial/aura/model.ts`).
- **Kira**: the name on five Wasm cells (`kira-*.wasm` in `apps/web/public/cells/`). Their pinned operations classify notes, rank recall, set store permissions, admit across a membrane and sign Nostr events (the `ops` lists in `wasm-cells.ts`). The recall organ is `seed-recall.js`. The written docs do not define Kira further. **Aperture** is a project name that no code in this tree uses yet.
- **Scion**: the compiler for an organ she proposes. **Pearl**: what she keeps from breaking things: a retention suite that candidates are run against, and founding lessons called scars. **Spatial**: the one workspace design every screen follows (`docs/foundations/SPATIAL-DESIGN-RULES.md`). **Auma Lingwa**: her language, with its script and curriculum in `apps/web/public/app/auma/`.

## Run it

RAN by its authors, on one machine: the results of every line are in [docs/RUN-RECORD.md](docs/RUN-RECORD.md), the two `vitest` lines with `--maxWorkers=3`. Each line ran once, except the app line, which ran again after a correction to the export. That is a record, not a promise that these succeed on yours.

```text
pnpm install --frozen-lockfile
PORT=<a port nothing listens on> node server/build-preview.mjs
pnpm run x6:start
node --test server/*.test.mjs deploy/ci/*.test.mjs deploy/cloudflare/src/__tests__/*.test.mjs
node --test deploy/cloudflare/src/__tests__/worker.spec.ts
pnpm exec vitest run packages/client/ui-layout/tests scripts/spatial-catalogue.spec.ts
pnpm exec vitest run packages/experimental/webworker-runtime/tests
node server/cloudflare-bootstrap-cli.mjs --dry-run
```

- Node 24.9 or newer and pnpm 11.28.5 are pinned in `package.json`. `pnpm run x6:start` runs `server/local-host.mjs` on 127.0.0.1, with owner values from `X6_OWNER_EMAIL` and `X6_OWNER_PUBLIC_KEY_HEX`.
- **Warning:** `node server/build-preview.mjs` posts to a host on `http://127.0.0.1` at `PORT` (default 4610), before replacing an earlier build and when it finishes. A host listening there, yours or any other program, is changed. Set `PORT` to a port nothing listens on, as above, when no running host should be touched.
- **A copy without `.git`, and an offline install.** The build reads the commit with `git rev-parse HEAD` and exits 1 when there is none. Set `DSH_CLIENT_COMMIT_HASH` instead, to any value of 7 to 40 hexadecimal digits, such as `0000000`: `scripts/client-build-environment.ts` takes it in place of Git, refuses any other shape and keeps the first seven. An install with `--offline` needs the registry metadata to be in the pnpm cache already, as well as the packages in the store; without it, install online. Both RAN.
- Do not start with `pnpm run x6:build`: on a fresh clone it is reported to fail (`UNRESOLVED_ENTRY`) because it needs the `lib/` output that `pnpm run build:lib` or the preview build produces. UNVERIFIED here.
- **Edit the placeholders before a deploy.** The node name, host, account id and repository are placeholders: `your-node`, `node.example.invalid`, a zero account id and `your_org_x/your-node`. They are in `deploy/cloudflare/wrangler.toml` and also written into code, so a new node edits them there too: the Worker name in `server/deploy-cloudflare.mjs` and `deploy/cloudflare/src/cloud-brokers.mjs`, the origin in `server/seed-cloudflare.mjs`, in `server/cloudflare-bootstrap-cli.mjs` (which refuses any other `--url`) and in four scripts in `deploy/ci/`, and the repository in `server/deploy-cloudflare.mjs` and `cloud-brokers.mjs`. `grep -rlE 'your-node|example\.invalid|your_org_x' server deploy .github` lists every file that holds one. `deploy/cloudflare/README.md` is the guide. Some code comments cite a document called NORTH-STAR, which is not in this tree.
- **The deploy script asks GitHub first.** `server/deploy-cloudflare.mjs` only prints its command unless `--deploy` is given. Before a deploy it uses the GitHub CLI (`gh`) to ask whether the repository's production environment already holds the Cloudflare credentials. If `gh` is missing or cannot answer, it refuses unless `--emergency` is given too.
- Give the node a private repository of its own. The head sync commits the node's world to `main` of the configured repository, never the shared source repository.
