# `@deepseek-ai/dsh-experimental-webworker-runtime`

English | [中文](README.zh.md)

## Summary

The browser worker host: the whole harness plugin tree runs inside one dedicated Web Worker, for preview deployments and packaging regressions ([experimental group](../README.md)). The worker inflates a packed VFS image off its download and mounts it in memory, loads its modules through a CommonJS wrapper loader, and serves the page over a postMessage tunnel that speaks plain HTTP. Use it when a preview must run the packaged harness without a Node host.

## Use this package

The public npm package exposes the runtime library at its root, the self-contained browser Worker at `./worker`, and the page connector at `./client`. Deployments supply and serve the VFS image separately through the [packer](../webworker-packer/README.md); installing this library does not add a profile layer. The root also exports the module-proxy and replacement tables used by the packer.

Three build artifacts and one source-owned process layer:

- **`lib/index.js` (assembly library)** — `createWorkerHost`/`startWorkerHost` mount the base image and any ordered data overlays (`storage/`), register the image's lazy archives, install the module loader (`module-system/`) and the `process` shim, boot the tree through the image's own `dsh-app-boot`, and hand the tunnel its serving seams. Overlays may replace files only under `home/` and `workspace/`; they cannot replace the base manifest or modules. The image layout contract (`image-layout.ts`: virtual root, manifest path, lazy archive directory, empty directories) and the manifest (`image-manifest.ts`: profile, installation, the `lowered` wrapper-contract gate, lazy archives) are shared with the packer. The Worker boots the manifest's shipped profile as the launcher does: the image's app-boot initializes `home/profiles/<profile>/` from the shipped template, resolves bundles from the installation manifest the image carries alone, and composes the bundle layers, the profile patch, and the home patch. The profile context, the launch environment snapshot, and a `PluginPackages` service without a runtime resolution are provided as the launcher provides them; the Worker loader owns module resolution. The profile context carries no command-line overlay; the image's home patch (`home/cordis.patch.yml`), which the packer writes from `PLATFORM_ENTRY_CONFIG`, keeps JSONL Session logs plaintext. ConfigEditor persists overrides in the profile patch, reconciles each write, and Loader commits live values. The Worker commits `appReady` once the tunnel serves, so HMR loads and applies profile changes live; the Worker's ES module cache stays empty and the `process` shim reports no entry script, so HMR compares and replaces no loaded modules. Plugin management lists and switches the installation's optional bundles, and its package operations fail with the `execa` refusal. Configuration edits last for the current Worker lifetime.
- **Lazy archives** — the manifest registers each page chunk the packer moved out of the base image by path and size, with its archive name relative to the image URL. Existence, stats, and listings answer at once; the first asynchronous read (`fs.promises.readFile`, `fs.promises.open`, `fs.createReadStream`, `fs.promises.cp`) fetches and inflates that archive once for every waiting reader, checks it against the registration, and mounts its files without publishing a mutation. A failed fetch rejects the read and leaves the files registered, so the next read fetches again. Until then, synchronous reads, writes, appends, truncation, chmod, rename, and link of a registered file fail with `ERR_DSH_VFS_DEFERRED` naming the archive; unlink and recursive removal drop the registration, and seeding the path replaces it. The archive name derives from its content digest, and the fetch checks only the registered paths and sizes, not the digest. An image that registers lazy archives must be passed as a URL.
- **`lib/worker.js` (worker bundle)** — the assembly plus this package's Node-compatibility layer as one self-contained ES module. The module proxy table (`module-proxies.ts`) is the only platform fork: `node:*` builtins over VFS/tunnel/browser primitives, structural stubs that fail loud on the console for what a browser cannot do, and native/binary package replacements. `node:module` supplies `createRequire().resolve` and `.resolve.paths()` over the image package root, so unchanged packages can discover manifests without evaluating their modules. `node-addon-require-builtin` answers the Node v24.18.0 internal modules that the vendored Loader, app-boot, and HMR read without `--expose-internals`: the cascaded ESM loader's `resolveSync` and `import` over the Worker loader, with Node's `ERR_MODULE_NOT_FOUND` and `ERR_PACKAGE_PATH_NOT_EXPORTED` codes, and an empty `loadCache`; and the CommonJS loader, package reader, `modules` binding, and resolve-cache members that HMR replaces, which refuse when called. `process.versions.node` reports `24.18.0`, so `ModuleLoader.fromInternal()` and the Loader's `internal` reach that cascaded loader. `node:path.win32.isAbsolute` and `node:util.inherits` follow Node; other `win32` members throw. The `node:util` JSON-data comparator compares own enumerable properties, preserving Node admission decisions for recorded fields such as `__proto__`. The global `process` shim carries Node detection fields including `title`, preventing Worker execution from entering DOM-only branches; Node’s `global` alias references the same `globalThis` object for image-loaded packages. The pack-time parser reports statically named module requests, including module-scope direct calls of the form `createRequire(import.meta.url)('pkg')` through a named `node:module` or `module` import, to the packer's reachability walk. Stored, CommonJS-obtained, and rebased `createRequire` calls require image entry seeds. Lowered bodies read named and default imports through the required module object at each reference, so a module in an import cycle observes a binding once the exporting module initializes it; in a module with such imports, an assignment to an imported binding, a direct `eval`, and a declaration using the reserved `__dsh$` prefix fail the pack. VFS mutations drive `node:fs` callback, polling, and promise watchers, whose listeners run in the async context where the watcher was created rather than that of the writing code; open descriptors retain file identity and access mode across rename, replacement, and unlink, `FileHandle.stat({ bigint: true })` reports the same device and inode identity as a path stat while the name still refers to that file, and `FileHandle.chmod()` updates the opened file identity; `readable-stream` supplies `node:stream/promises` completion and pipeline helpers and the stream state machine used by file streams and unchanged image packages such as Chokidar and readdirp. The maintained `string_decoder` package supplies `node:string_decoder`, retaining incomplete multibyte characters between chunks. AsyncLocalStorage carries sync-stack causality across `await` through the snapshot/restore faces the pack-time lowering injects. The worker holds no compiler: an image the packer did not lower is refused at mount. The callback `fs.realpath.native` alias resolves within the mounted VFS and supports `util.promisify`.
- **`src/shell/` (the worker's own process layer)** — a browser worker cannot fork, so `node:child_process` is not a stub but an implementation: `spawn` starts the command in its own Web Worker — this same bundle, told by its first frame to be a shell process — and reports it through the `ChildProcess` surface the subprocess service consumes. The command runs off the host's thread, `SIGKILL` terminates it whatever it is doing, and it reaches the VFS only by message (the host serves those frames). Worker platform executables preserve native-package protocols such as Landlock without replacing their JavaScript packages or coupling their implementations to `node:child_process`; `xdg-open` sends one VFS text file to the page's read-only viewer, so desktop-opener actions such as **Open configuration file** show the file in the page; ordinary commands use the package's evaluator and coreutils command table. The grammar is `@yarnpkg/parsers`' `parseShell`, while `execSync`/`fork` still refuse because they need a real process.
- **`lib/client.js` (page half)** — startup has two independent stages. `chooseWorkerHostSource({ image?, fixtureManifest? })` optionally owns the boot barrier and fixture manifest: without `preview-fixture` it waits at the source chooser, while a valid query selects directly; either path returns ordered overlays. `connectWorkerHost(worker, { image?, overlays? })` remains the public base-runtime connector; callers that skip the chooser get an empty overlay list. `apps/web` invokes both and supplies its statically bundled Worker. The opening `init` frame carries the base and ordered overlay URLs, the boot payload delivers the structured index-injection table, and `applyIndexInjections` executes it before the shell entry runs. Script preload rows are advisory and skipped because `/plugins` resources resolve only through the tunnel; `loadBundle` fetches each combo on first demand, embeds its tunnel-only source map as a Base64 data URL, and executes the script as a Blob. Before the shell entry runs, the page reads `GET /__assets__`, which the tunnel answers with an uncompressed tar of every package asset in the image, and supplies `resolveAsset`, which maps each `plugins/<package>/assets/<path>` reference a bundle passes to `require.asset` to a Blob URL of those bytes. The worker's unsolicited `view-text` frame opens the page's modal text viewer. The tunnel also exposes fetch-shaped transport, the independent file-upload carrier, and the API client. Request frames preserve Blob bodies through structured clone and transfer `ReadableStream<Uint8Array>` ownership. The Host Worker streams both forms into the route, so neither browser thread creates a complete byte array for a generic-file upload. A Remote stream's uplink crosses as `stream-uplink-item` / `stream-uplink-end` frames into an unbounded `TunnelUplink` that drops items arriving after `end`: the page and its worker are one trusted same-origin boundary, so the Host inbox cap does not apply.

Callbacks and timers registered under an explicit root context retain its empty stores, so they cannot inherit an unrelated transaction.

Acceptance lives in `apps/web/tests/preview-boot.e2e.ts`, which serves the real built pages and drives the pre-boot chooser plus Worker activation in headless Chromium. The empty selection exercises first-run startup. The `vfs-example` overlay supplies ordinary workspace files and plaintext persistence artifacts for cold Workspace/Session discovery, tool presentation, subagent navigation, and history paging without a model request. The showcase mixes empty, whitespace-only, and non-empty reasoning with a long multiline command and a parent-path file link; these are authored fixtures, not live model output. A second root Session, `preview-turn-spacing`, carries three multi-step Turns whose bodies compare the tightened process-row spacing with the reply clearance. The [packer](../webworker-packer/README.md) prepares current-generation successors from committed historical logs in Node; those source logs remain byte-identical in the overlay. The fixture generator owns the acceptance test's current projection cache. The chooser reserves WebFS as a separate user-authorized source; that provider does not read the built-in fixture.

The [built-bundle import sweep](tests/compile/transform-corpus-check.ts) checks bare Node imports after the library build. Its Dockkit exception accepts Node’s unknown-`.css`-extension refusal for any stylesheet rather than one pinned path; another extension, error code, or message, and an unexpectedly successful exempt import, remain errors.

## Wasm cell execution

`createCellHost` keeps admitted modules and serializes calls through one dedicated execution worker. Each ABI export has a fresh capped fuel grant. An independent 5000 ms deadline covers worker startup, Wasm instance/start execution, ABI validation, allocation, execution and fuel inspection. Expiry returns `TIMEOUT`, terminates the worker and discards all its instances; a later call recreates the worker from already admitted modules. Queued calls and the separate fetch/admission phase are not part of that execution deadline. `dispose()` stops in-flight work, settles queued calls and closes the host permanently.

Browsers need nested workers and permission to execute `blob:` workers. Hosts without that facility must supply a real independent worker transport through `createWorker`; there is no synchronous fallback. Worker creation or execution failures return `CELL_WORKER_UNAVAILABLE` or `CELL_WORKER_FAILED`. This isolation covers Wasm cells, not arbitrary organ JavaScript.

Microverse request and receipt serialization with `cellCanonicalJson` accepts only safe integers, rejecting fractional, non-finite and unsafe numbers at every nesting depth. Returned JSON results keep finite floating values for consumer compatibility; callers must not use the integer-only serializer for arbitrary floating-point application output. Pins and ABI export requirements are unchanged.

The X6 loader registers built-in tools independently before mounting HEAD entries, then opens presence connections after those initial mounts finish. Reconciliation preserves unchanged nonmounted entries and their diagnostics; changed entries are retried, and support modules retain no active fiber. Published-head metadata must pass manifest validation before a successful read can clear recovery warnings. Bounded status drops diagnostic detail before compact entry states, retains head-lag and persistence warnings, and counts inventory omitted by the byte limit.

## Model Experience

None, as this package only hosts the tree in a browser worker and answers its `node:*` calls; model-facing registration and request assembly belong to the plugins it boots.

None; the browser transport adds no cache of its own, and the configured provider plugin owns request cache fields.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- **The worker composition writes plaintext session logs** (`compression: 'none'` in the image's home patch; ConfigEditor rejects edits to that row's config): it carries no Zstandard codec, so exported logs are `.jsonl`, never `.jsonl.zstd`.
- **Aukora cloud backups recheck the local writer before snapshot dispatch**: read-only status or a changed IndexedDB writer epoch prevents publication; an unreadable epoch reports a failed backup. This local check cannot retract an already dispatched request or make the local epoch and edge snapshot atomic.
- **A successful cloud response needs a usable snapshot identity** from its ETag header or JSON body. Without one, the outcome stays unknown and automatic uploads stop until reload; pending changes and the previous local parent remain. A resolved upload promise is not a verified-save token.
- **`node:dns/promises`, `node:vm`, `node:repl`, `node:net`, `node:sqlite`, `node:worker_threads` are structural stubs**: imports remain available for image packaging; every exposed call reports its refusal on the console and throws with Node's `ERR_FEATURE_UNAVAILABLE_ON_PLATFORM` code. Rows needing native DNS, a real process, a Node REPL, or realm isolation cannot run here.
- **`node:assert/strict` supports truthiness assertions only**: for falsy values, the callable default and `ok` throw `ERR_ASSERTION` with the supplied message or generic text, or rethrow a supplied Error unchanged. Other assertion APIs are absent.
- **Native TLS listeners require a Node Host**: the worker's `node:https.createServer` rejects activation rather than substituting plaintext. The preview's internal HTTP tunnel does not bind sockets; browser-facing HTTPS belongs to its deployment server.
- **Desktop product telemetry is unavailable**: `got.post` reports an explicit worker-host refusal. Got and its Node HTTP dependencies are excluded from the browser image; Desktop reporting remains disabled in the preview composition.
- **Host package commands are unavailable**: `execa` reports an explicit worker-host refusal; the preview cannot run pnpm, install plugins, or install native dependencies.
- **Pi agent execution is unavailable**: the `@earendil-works/pi-coding-agent` replacement permits metadata imports and rejects SDK calls with `ERR_FEATURE_UNAVAILABLE_ON_PLATFORM`. The image excludes its native CLI and terminal UI dependencies. Native DSH retains the full OAR runtime registry.
- **pi-ai model requests are limited to Moonshot AI and DeepSeek chat completions**: the replacement carries the installed catalogs for `moonshotai` at `https://api.moonshot.ai/v1`, `moonshotai-cn` at `https://api.moonshot.cn/v1`, and `deepseek` at `https://api.deepseek.com`, streaming through browser `fetch` over the existing settings and credential path. Other providers and protocols retain the explicit worker-host refusal; provider access still depends on browser CORS and deployment policy.
- **PTC Node programs are unavailable**: the process shim exposes `/dsh/bin/node` as its executable identity so the provider can activate, but the Worker has neither a Node executable nor `stripTypeScriptTypes`. Program execution fails before launching a child.
- **Office conversion requires a Node Host**: the LibreOffice kit replacement rejects converter creation with `unavailable`. The browser image excludes the kit and its engine dependencies; the Office preview reports that conversion is unavailable.
- **Module reload is not transitive HMR**: the Worker's ES module cache stays empty, but its own loader reuses a normalized VFS path's exports only while stored bytes match the successful evaluation. Changed JS/JSON files reload on their next direct `require` or import; active CommonJS cycles retain partial exports. Cached importers and package-resolution metadata need explicit eviction/reloading; held references are not replaced. The preview image changes no module files: package operations fail with the `execa` refusal.
- **Ball paths require matching bytes**: the loader verifies exact stored bytes for canonical `<root>/home/balls/<64-lowercase-sha256>.js` paths before execution or cache reuse, including absolute, relative, file-URL and package-resolved aliases. Mismatches throw `Ball integrity check failed`. Restore the original bytes or use their correct new hash and path. Explicit `ball:<sha256>` imports still evaluate afresh.
- **Worker `node` lifetime is bounded**: directly injected timeout, interval and immediate handles keep a command alive and are cleared on completion, exit, error or the 30-second deadline. Returned promises also share that deadline; timeout returns a nonzero exit status. Timers in required modules, `globalThis` timers and external workers are not tracked or cancelled. Return their completion promise explicitly; a synchronous loop still cannot be preempted in the host worker.
- **The Node internal modules answer only their HMR-replaced members**: the CommonJS loader, package reader, `modules` binding, and `getOrCreateModuleJob` refuse when called, and the Worker's own `require` does not route through the CommonJS loader, so replacing `Module._resolveFilename` or `Module._load` does not change Worker resolution.
- **CommonJS `require('stream')` returns the module namespace, not Node's `Stream` constructor**: code that passes it to `util.inherits` fails at load.
- **A lazily supplied file has no synchronous read before its archive arrives**: a consumer must read it asynchronously first; the Host's on-demand Client chunk route does.
- **Filesystem watchers observe only the mounted VFS**: image seeding is silent and the VFS has no symlinks or external writers. `persistent`, `ref()`, and `unref()` preserve the Node API but cannot control a dedicated Worker's lifetime because browsers expose no ref-counted event loop.
- **Worker confinement is a VFS boundary, not kernel Landlock**: `read-only` and `workspace-write` run the unchanged `@deepseek-ai/node-addon-system/landlock-run` JavaScript and launcher argv, but the process layer implements the logical `landlock-run` executable and enforces its grants on every shell filesystem request. `full` therefore covers the Worker command table and mounted VFS only; it does not claim arbitrary native-process execution or Linux kernel isolation.
- **The worker bundle pins a path inside `@yarnpkg/parsers`** — the build resolves the package's own `lib/shell.js` instead of its root, whose barrel also re-exports the Syml parser and so drags js-yaml into a bundle that never parses that format (around 175 kB, plus its module body at worker start). The path is derived from the package manifest, so a layout change fails the build rather than reinstating the barrel; upgrading the dependency means re-checking that the shell parser still lives there.
- **The shell is not bash**: no loops, functions, `case`, job control, or process substitution — the grammar stops at pipelines, `&&`/`||`, subshells, groups, redirections, and expansion. `&` runs its command to completion in place, `sed` accepts only substitution scripts, patterns are JavaScript regular expressions, and the command table holds coreutils only (no `git`, no network tools).
- **A shell process has no synchronous filesystem**: it reads and writes the host's VFS by message, because blocking on a reply would need `SharedArrayBuffer`, which requires a cross-origin isolation GitHub Pages cannot grant. Directory-walking commands therefore cost one round trip per entry, and two concurrent commands can interleave their writes.
- **Transport, worker-host, and page-half coverage needs a browser-grade harness** — the per-file coverage gate is unmet for those modules; unit specs cover storage, ALS, the transform, and the stub contracts.

## X6.1 local runtime

`tree_undo` currently refuses with `PEARL_QUALIFICATION_MISSING_OR_STALE` because it has no executable admission issuer; this is not an expired patch qualification. The underlying `tree_patch` and `tree_undo` operations serialize mutations and retain full prior module, config and disabled state, including config-only changes. Optional `expectedEpoch` and `expectedBallId` are checked after acquiring the mutation queue. Legacy specifier-only history is retained, but undo refuses to guess missing config; restore a complete snapshot instead. Pre-change snapshot failure stops the edit.

Mutation results and `body_map` expose independent `prepared`, `activated`, `localSaved`, `remoteSaved` and `receiptSaved` fields. Local save awaits an IndexedDB transaction; failures retain dirty paths. Remote save means only the exact manifest acknowledged by the named `remoteTarget` endpoint, not Cloudflare backup or GitHub publication. Each committed patch and undo appends to the existing receipt chain; a receipt is reported saved only after local persistence succeeds.

The local host owns manifest selection through one serialized HTTP/WebSocket publisher. New heads require the selected parent and epoch, valid manifest and module hashes, and available historical modules. Replaying the selected manifest is idempotent. Competing proposals are retained under the private mirror's `balls/forks/` directory and return `REBASE_REQUIRED`. VFS deltas and snapshot uploads cannot overwrite the head or immutable module store.

Snapshot and staging-parent validation accepts legacy manifest IDs and canonical IDs binding every own manifest field except `ballId`. Fresh governance candidates created by `tree_patch` use canonical IDs and remain inert until owner approval and host admission; existing staged candidates are not rewritten. Ordinary candidates keep their existing ID and qualification policy. Load this compatible runtime before adopting a canonical head; older bundles can reject its snapshots. The default edge passkey-only policy requires one governance entry changed and all other entries unchanged, and does not certify behavioral retention.

`ball_put` only stages immutable code and metadata. A tree edit selects the module. Boot adopts the host's exact selection and retains a differing local head as a fork; changed Seed source is exposed as `seedCandidates` instead of silently rewriting the selection. Peer notifications follow host acknowledgment, and receiving tabs confirm the host selection before reconciling. A failed reconciliation restores the previous entries and does not publish the failed target. Snapshot restoration advances the head epoch rather than moving history backwards.

Receipt verification recomputes every checkpoint envelope hash, validates receipt count, sequence, covered last receipt, Merkle root, signature and signer continuity. An independent supplied public key or the existing local key anchors identity; without one the result explicitly reports chain consistency only. Damaged or missing signing identity is never silently regenerated when checkpoints already exist. The signing key remains local in IndexedDB and is excluded from both delta and snapshot export payloads.

Scion compiles an explicit multi-file TypeScript/ESM organ snapshot in a separate, disposable browser worker. Its offline esbuild-wasm 0.28.2 artifact is checked against its source-pinned size and SHA-256 before initialization. Inputs are bounded to 128 files and 2 MiB, imports resolve only within that snapshot or the host-owned exact external list, and the parent terminates the worker at its deadline. The result includes a compiler pin, source/recipe root and output digest. Compilation and `ball_put` stage inert source without executing or selecting it. Activation still executes the selected organ in the main runtime and is not an isolated trial. Scion’s browser-side runtime closure compiler and its release-promotion actions remain explicitly unavailable; host capture and runtime selection below are separate.

`scion_grow` joins typed compilation to the existing live Seed growth cycle. Supply a named Seed organ, up to 127 source files and explicit acceptance cases; a generated entry validates the exported organ name before registration and is included in the compiler input/output hashes. Cases are frozen and hashed before compilation, limited to 32 cases and 64 KiB, with exactly one expected result or error per case. Growth requires acknowledged local preparation, unchanged selected HEAD and writable storage. The existing cycle performs live install, acceptance and refusal/undo; its phase and separate acknowledgements remain visible. Case outputs use a bounded JSON-safe report with explicit non-JSON/truncation flags. Success additionally requires the exact output hash in the mounted registry, selected entry and active fiber. A phase-less or interrupted cycle is uncertain and must be inspected before retrying. Acceptance calls can have real effects, and activation is not an isolated trial. This is typed organ growth, not a full runtime compiler or automatic release promotion.

Memory v2 preserves the original v1 file and writes an append-only sidecar only for explicit mutations. Immutable content IDs, parent ancestry, clamped source trust, corrections and descendant-suppressing tombstones retain provenance without treating memory as authority. Recall can match a predecessor but discloses only its active terminal correction. Fresh bounded v4 session scans retain complete anchors; compressed, malformed, missing or over-budget sources return `UNDETERMINED`, not a false `EMPTY`. Explicit mutations await local IndexedDB acknowledgement separately from VFS write and do not claim remote backup. Local preconditions and temp-rename readback are not cross-tab or distributed CAS.

Local mirror delivery uses immutable sequence-numbered batches in the existing IndexedDB store, atomically committed with local changes. Pending paths and tombstones fence stale hydration; recursive deletion clears stored descendants before current subtree recreation. One sender retries oldest-first and removes only the exact acknowledged batch. Checkpoint files join the same delta queue; no stale whole-VFS bootstrap is uploaded. The local host validates and serializes batches and snapshot reads, keeps a private recoverable pending journal and replay receipts, and preserves source mtimes. This is local ordered delivery, not cloud backup or distributed conflict merging. Old unordered snapshot/delta writes are refused until that client reloads. `auma_snapshot(action:"sync")` awaits the outbox, and `body_map` summary exposes its state.

Updated writers admit at most 256 pending mirror batches and 32 MiB of complete serialized batch records, with 50,000 entries per batch. These fixed duplicate-payload safety limits are not browser quota estimates, and older retained clients do not enforce them. Admission reads the durable queue inside the same transaction before changing local content or sequence metadata; existing batches are never dropped or coalesced. A full queue refuses the new save, keeps dirty paths and new VFS work in the open tab, and reports `MIRROR_QUEUE_FULL`; keep that tab open and preserve its unsaved work. Exact acknowledged delivery frees space and schedules a save retry. Explicit sync drains existing work before retrying a capacity-blocked save and never claims success while that save fails. A single oversized change reports `MIRROR_BATCH_TOO_LARGE`; draining cannot make it fit. Local-only writes remain admissible. `localSave` reports unsaved-path count, error and capacity refusal separately from mirror delivery state; only a successful flush clears the save error. Queue usage counters are advisory across tabs; admission remeasures inside its transaction. Browser quota exhaustion can still reject any transaction.

Authoritative local HEAD edits acquire a single transient peer writer lease before activation. The host validates the selected manifest before granting or renewing a lease, publishing a descendant, or repairing the home metadata copy. Malformed JSON, a JSON null value, invalid entries and digest mismatches fail with `SELECTED_HEAD_INVALID` before any of those writes; they are never treated as empty-genesis authority. Exact lease release remains available so a caller can relinquish coordination after corruption is detected. Lease changes and HTTP/WebSocket head publication use the same host queue; owner, expiry and a persisted monotonic generation fence publication in addition to parent/epoch CAS. Runtime edits renew and release their lease; a live grant cannot be replaced even by its owner, so uncertain acquisition/release waits for exact release or expiry. Stale or competing writers stop before activation, and rejected candidates remain retained. A later edit adopts a changed host selection while retaining its local fork and asks the caller to retry against the new ballId. The lease is concurrency coordination under the existing session capability, not a new credential or a strong trust boundary. It does not provide cloud coordination or merge independent clients’ private VFS data.

Runtime `buildSha` is stamped into the worker at build time, with an explicit `-dirty` suffix for source changes. `buildIdentity` names that source revision, source-dirty state, build time, the SHA256 of the prebuilt runtime worker input and the loaded content-addressed worker filename. The supported preview build rebuilds that runtime package before Vite stamps it. The host’s mutable repository revision is separately `hostSourceSha`; pushing main cannot relabel an already-running tab. Source-dirty checks cover packages, vendor code, the web app, build scripts and root package/lock files, not a reproducible full dependency closure. Unstamped and watch builds report `UNVERIFIED`; watch output does not reuse a clean one-shot stamp. This is bundle identification, not a reproducible-build or signing attestation.

Seed organ install/undo/retire wrappers preserve the selected-head mutation acknowledgements. Unconfirmed local/host/receipt persistence returns `ok:false` with `outcome:persistence-unconfirmed` while reporting whether activation already happened. Seed cycle does not mistake that state for an unexecuted install or issue a second destructive fallback after an activated undo. Retire now disables the selected entry reversibly instead of undoing it and deleting a restored registry entry. Install and undo carry an exact captured head precondition into serialized execution.

Mirror wire metadata, date ranges, symlinks and ordered parent/type transitions are preflighted before journaling. Acknowledged replay bypasses filesystem preflight and never reapplies old bytes; genuine interrupted I/O remains fail-closed for recovery rather than being silently skipped. Mirror hydration commits its IDB import before changing the VFS. Persistence becomes durable only after hydration and hooks are installed.

Receipt append/checkpoint operations share one per-VFS queue across module hot reload, covering asynchronous key/signature work without changing the signature protocol or creating an identity. This is not cross-tab CAS. Writer leases have a non-renewable 60-second operation deadline; an indefinitely awaiting activation cannot renew the host lease forever. The selected HEAD is committed before its recoverable home metadata copy; exact replay can repair that copy.

The mirror journal persists a per-entry progress cursor, so recovery resumes an unfinished suffix rather than replaying an old prefix beneath an ancestor replaced later in the batch. A crash between an entry and its cursor can repeat only that idempotent primitive. Imported file/directory replacements atomically clear stale IDB descendants and retain subtree-reset metadata; local-only signing identity is protected from ancestor replacement. File fsync and rename do not claim a cross-filesystem transaction or guaranteed power-loss durability.

If the host loses its selected HEAD while a browser retains an existing local head, mutations stop before activation with `HEAD_AUTHORITY_MISSING` and retain that local fork. The runtime does not silently choose an old tab as recovery authority or publish an invalid descendant into an empty host. Only the first empty-genesis Seed bootstrap can initialize selection automatically; restoring an existing fork is an explicit recovery decision.

Legacy memory migration groups identical required content IDs into one deterministic fact with all original keys retained as aliases and all raw variants preserved privately. Correcting or tombstoning that fact affects every alias; aliases are not independent histories. Corrections carry the aliases forward, lookup/search remain correction-aware, and raw migration variants never enter recall responses. Duplicate-ID validation remains strict elsewhere, no timestamps/parents are invented, and the original v1 file is unchanged.

Mutation errors distinguish confirmed pre-activation refusal (`not-applied`) from partial/uncertain execution. Lease/CAS/metadata refusals do not claim activation or rollback.
