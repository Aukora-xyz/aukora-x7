# 将冲突备份保留在云端镜像之外

[English](guide.md) | 中文

## 变更

云端镜像验证此前接受 `.conflict-backup` 目录及其内容。现在，任何包含这一精确路径段的路径均会被拒绝。引导初始化扫描在读取内容之前排除这些目录。此规则不排除 `.conflict-backup-old` 等相似名称。本地恢复备份的创建和本地宿主镜像传输保持不变。

传入的引导初始化批次和增量若涉及被排除的路径，会以 `INVALID_MIRROR_PATH` 失败。位于这些路径的现有云端条目或重置记录会使无条件快照读取和完整状态读取返回 HTTP 400 及同一错误代码，而不是从快照中消失。精简状态及无响应体的 HTTP 304 响应不验证全部已存储的路径。此变更不会移除已存储的数据、协调不可变的排队批次，也不会修复历史具名回滚恢复。源代码行为不能证明已在生产环境激活。

## 迁移

1. 部署前，检查现有云端状态、已保存的 seed 包或待处理云端批次是否包含 `.conflict-backup` 路径段。验证浏览器的云端发件箱在传输前阻止被排除的路径，包括已排队批次中的路径；仅在服务器端拒绝无法阻止上传。保留本地恢复备份、待处理输出及交付证据。不得仅为检查路径是否符合条件而读取或传输私有备份内容。
2. 若存在此类状态，停止部署，并为经过审查的状态协调另行取得授权。不得静默过滤已存储的条目或重置记录、删除备份、改写不可变批次或 seed 包，也不得重置客户端隔离记录和 lineage。不提供自动迁移。
3. 对于全新的引导初始化，通过[引导初始化驱动程序](../../../../deploy/cloudflare/README.zh.md)准备新包；不得修改已获批准或已部分上传的包。确认准备好的条目排除 `.conflict-backup`，并保留符合条件的相邻路径。传输仍需获得对该确切包的批准。
4. 激活前，验证云端接纳检查拒绝被排除的路径、现有被排除记录会导致拒绝操作且不发生修改，以及本地恢复备份仍可使用。部署及线上访问检查需要另行授权。
