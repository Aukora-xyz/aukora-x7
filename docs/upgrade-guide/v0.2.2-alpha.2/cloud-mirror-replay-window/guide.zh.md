# 有界云端镜像回放窗口

[English](guide.md) | 中文

## 变更

MirrorDO 此前永久保留协议确认，回执达到 4,096 条时停止。其源代码发布路径现已集成有界保留。这并非已在生产环境激活的证据。

该窗口为每个客户端最多保留最新的 64 条确认，全局最多保留 4,096 条，并保护每个客户端最新的确认；全局容量压力可能使某个客户端的窗口缩减至不足 64 条。若重试对应的确认已被裁剪，返回 HTTP 409 `MIRROR_REPLAY_EXPIRED` 并尝试保留冲突。冲突存储已满时，改为返回 HTTP 507 `MIRROR_CONFLICT_CAPACITY_EXCEEDED`，并附带 `conflictCode: MIRROR_REPLAY_EXPIRED`。两种结果均不会重新应用该批次或确认交付成功。

此集成保留永久客户端序列号／摘要隔离记录、全局 lineage／修订版本、内容、删除标记、引导初始化状态和用户记忆回执日志。256 个客户端的上限及内容／冲突限制保持不变。具有有效隔离记录且最多包含 4,096 条确认的库存，在下一次成功发布时减少确认数量。格式错误、不完整或缺少隔离记录的库存必须导致拒绝操作，并需要明确且可审计的恢复，不能凭猜测迁移。

## 迁移

1. `/_mirror/delta` 的调用方必须将 HTTP 409 `MIRROR_REPLAY_EXPIRED` 及其冲突容量不足时的 HTTP 507 响应作为未解决的交付处理。保留待处理的本地输出，在手动解决前检查冲突及当前云端快照；不得盲目修改标记、变基或重新发送旧批次。
2. 保留现有客户端序列号／摘要隔离记录及全局 lineage／修订版本。不得通过删除存储记录来绕过验证或重置交付历史。不存在独立迁移命令；发布将裁剪与成功发布的写入一并原子应用。
3. 激活前，验证仍保留确认的重试返回原始确认、已过期的重试绝不重新应用批次，以及浏览器保持未解决的交付可见。生产环境验证需要另行取得部署和访问授权。
