It is written to be checked line by line; the front page ([README.md](../README.md)) is the short version, and [ARCHITECTURE-MAP.md](ARCHITECTURE-MAP.md) draws how the parts fit.

**Maturity labels.** Each item carries one or more of these, and no others:

- **IMPLEMENTED**: code and tests for it are in this tree.
- **RECORDED RUN**: shown in [docs/RUN-RECORD.md](RUN-RECORD.md), one run of an earlier tree of this repository, by its authors, on one machine. That run had 5,502 test cases: 5,399 passed and 90 failed, 89 of them listed in [docs/KNOWN-RED-TESTS.md](KNOWN-RED-TESTS.md) and one found by that run and added there. "Green in the RECORDED RUN (of an earlier tree)" below means a test file was in one of the recorded commands and is not on that list. The file of every one of the 90 failures is listed there with its count, so such a file had no failing case in that run. The run's logs do not ship.
- **INDEPENDENTLY VERIFIED**: nothing in this tree has this label yet. No one other than its authors has recorded a run of it.
- **UNVERIFIED**: claimed or written, but no test here holds it or no run shows it. Code may exist with no test that exercises it, or it was never run where it matters (a deployed node, a browser, a real passkey, a real model).
- **DIRECTION**: an aim. Not built as described.

## Summary

Aukora is a personal AI node that one person owns. Its AI, Auma, is built from small replaceable modules called organs, and she can write, compile, test and stage the next version of herself. What proposes never permits: a change to her own judges, a merge into her repository or a post to GitHub waits until the owner approves those exact bytes with a passkey, and the edge, not Auma, makes that check.

The edge is a Cloudflare Worker with two Durable Objects (its storage): HEAD, which selects the version of her that runs, and MIRROR, which holds a copy of her home. The agent runs in the owner's browser, on the inherited DeepSeek Harness runtime that makes up most of `packages/`; Aukora's own layer is the authority, self-change and recovery code named below. This tree is a prototype, exported by script from a running private node without that node's world (its data, keys, names and history). Every node starts at the same first version, the genesis head.

Where the weight is, by file:

- **An approval covers exact bytes and is spent once.** IMPLEMENTED; test files green in the RECORDED RUN (of an earlier tree). The edge ties each passkey challenge to the origin, method, path and body hash of one request. For a head move and for a GitHub post it spends the approval in the same storage transaction as the effect's own record; other approved requests spend it at the edge just before the effect runs. `deploy/cloudflare/src/aumlok.mjs`, `deploy/cloudflare/src/head-do.mjs`.
- **One rule decides what counts as a failed proof, and a test reads the source to hold it.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree). Only a proof that was checked and was wrong can move a lockout. A 1,093-line test parses the owner-identity source, follows aliases, and fails if a verifier is called anywhere else; its exemption list is empty. `deploy/cloudflare/src/proof-failure-rule.mjs`.
- **She compiles candidates of herself, and the parent grades them again.** The regrade is IMPLEMENTED (`scion-growth.spec.ts`, one unrelated case known red). The compile step itself has no test that calls it: UNVERIFIED. A candidate organ is compiled in a separate worker by the scion, her organ compiler, and run against the retention suite of Pearl, which is what she keeps from breaking things. A pass that the candidate reports for itself is ignored. `packages/experimental/webworker-runtime/src/x6/scion.ts`, `mirror/home/auma/seed/organs/seed-pearl.js`.
- **Identity, keys and judges sit in 25 sealed Wasm cells, which Auma calls as tools.** The edge calls none of them: its own identity and approval code is JavaScript (`deploy/cloudflare/src/aumlok.mjs`). The loader is IMPLEMENTED (`wasm-cells.spec.ts`, green). 24 of the 25 cells ship as binaries without their source, so that any cell matches a source is UNVERIFIED. Each is pinned by size and SHA-256 (checkable without running anything), has zero imports, and runs on a fuel grant in a worker that is ended after 5 seconds. `packages/experimental/webworker-runtime/src/x6/wasm-cells.ts`.
- **The owner has a way back in.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree). No restore against a real edge is recorded. A rescue page, a vault, a bounded archive, and a restore that writes only into an empty edge. `deploy/cloudflare/src/rescue-kit.mjs`, `deploy/cloudflare/src/recovery-restore.mjs`.

Counted in this tree: 26 organs in the genesis head, 25 Wasm cells with 169 named operations, 27 agent tools, 15 governance ids that only the owner's passkey can change, 58 edge modules of more than 22,000 lines with 94 test files, 175 spec files for the app and the browser runtime, and more than 3,500 test cases written.

Status: the tests are in the tree to be run. Some are known red, each listed with its count and reason in [docs/KNOWN-RED-TESTS.md](KNOWN-RED-TESTS.md). One run of an earlier tree of this repository, by its authors on one machine, is recorded in [docs/RUN-RECORD.md](RUN-RECORD.md): an offline install, the build, a boot of the local host and 5,502 test cases, of which 90 failed: 89 known red and 1 found by that run and still red. That run found one more failure, made by this repository's export; the export was corrected and that suite, run again, had no failure. It shows no deployed node and no browser session, so run it before you rely on it.

### Authority: AUMLOK and the owner's passkey

AUMLOK is the identity door: passkey enrolment, owner sign-in, devices, the seven words (the owner's recovery phrase), invites and exact-bytes approval. Code is in `deploy/cloudflare/src/` and tests in `deploy/cloudflare/src/__tests__/` unless a longer path is given.

- **Exact bytes, spent once.** IMPLEMENTED; test files green in the RECORDED RUN (of an earlier tree); no real authenticator recorded. The passkey signs a random challenge, and the edge holds that challenge bound to the origin, method, path and body hash of one request (`aumlokClass3Binding` in `aumlok.mjs`), so the approval is spent only on those bytes. It lives five minutes and is spent once. For her GitHub posts, `consumeClass3` in `head-do.mjs` spends the approval and reserves the body hash in one storage transaction. The reservation is never released automatically, also when the outcome is unknown, so a reload cannot post twice. The ledger holds 4,096 reservations and then refuses. Tests: `convergence-approval-fencing.test.mjs` (5 cases), `cloud-brokers.test.mjs` (29 cases).
- **The page asks for the bytes it showed.** IMPLEMENTED; test `packages/client/ui-layout/tests/outward-class3.client.spec.tsx` (3 cases, jsdom), green in the RECORDED RUN (of an earlier tree); no browser session recorded. For a staged GitHub post the page reads the request strictly, shows its full text, reads the file again at the click, and asks the passkey only if it is still the same request. `packages/client/ui-layout/src/client/spatial/aumlok/outward-class3.ts`.
- **Sign-in with the bound passkey, behind a gate.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree); no owner sign-in recorded. A session lasts 8 hours at most and is not an approval. Five wrongly signed passes within 60 seconds lock the door for 300 seconds. One case sends 100 overlapping wrong passes and asserts that at most five signature checks start. `aumlok.mjs`, `gate-lockout.mjs`, `owner-login-slots.mjs`. Tests: `owner-passkey-signin.test.mjs` (31 cases), `owner-login-gate.test.mjs` (14 cases).
- **One rule for a failed proof, made structural.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree). A lockout counter moves only when a cryptographic proof was checked and was wrong. Junk, an expired challenge or a library error never counts, so an outsider cannot lock the owner out. In `proof-failure-rule.mjs` only `proofOutcome` calls a verifier and only `countFailure` moves a counter, and an outcome carries a private brand that no other module can make. A passkey answer is screened first by the project's own parse (`webauthn-screen.mjs`), and a mismatch there is refused uncounted. `proof-failure-rule.test.mjs` (11 cases, 1,093 lines) parses the owner-identity source with the TypeScript parser, follows renamed and namespace imports, aliases, destructuring and `bind`, and fails if a verifier is called or a counter written anywhere else. One case makes every edge file that calls a verifier be listed as identity code or as not, with a reason, and the list of open exceptions (`OPEN`) is empty. Six of its cases plant a known way around the rule, such as a renamed, destructured or bound verifier or a counter written through `Reflect`, and assert that the scan catches each one.
- **A second device's passkey.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree); not run on real authenticators. An enrolled passkey approves "add a device" and gets a one-time code: 256 random bits, stored only as hashes, ten minutes, burned after five wrong tries. The new computer registers a passkey but only joins. It cannot sign in until an enrolled passkey confirms the exact key, shown as a six-digit phrase. `passkey-devices.mjs`. Test: `passkey-devices.test.mjs` (69 cases).
- **The seven words.** IMPLEMENTED; tested in `packages/client/ui-layout/tests/host-facts.client.spec.tsx` (its "AUMLOK phrase" and "AUMLOK root sealed by the seven words" groups), green in the RECORDED RUN (of an earlier tree); no ceremony recorded. The page draws seven words with `crypto.getRandomValues`, uniformly over 11,253,636,424,086 valid phrases (43.36 bits), and shows them once. The commitment it keeps is PBKDF2-SHA256 at 600,000 iterations, salted with the node's public key. The file header gives the reason for both choices. `packages/client/ui-layout/src/client/spatial/aumlok/aumlok-ceremony.ts`. The words seal a 32-byte root with AES-256-GCM. The node's Ed25519 key is derived from that root, and the sealed root is released only after the bound passkey asserts. `packages/client/ui-layout/src/client/spatial/aumlok/aumlok-root.ts`.
- **The night grant.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree); no grant used on a deployed node recorded. One passkey tap lets her add or replace ordinary organs alone, within 12 hours, 12 uses and 8 organs per use. Governance ids are never covered. `night-grant.mjs`, `night-grant.test.mjs` (21 cases).
- **She cannot change her own judges.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree). The list itself is Worker source, so changing it is a code deploy. `server/deploy-cloudflare.mjs` asks no passkey; who holds the deploy credential is UNVERIFIED. Fifteen ids are owner-only by name, and so is any entry that declares itself governance. Ten are organs: receipts, Pearl (her retention suite and founding lessons), Aura (her coherence reading), prediction, recall, memory, the body map, the superagent, the scion (the organ compiler) and boot. Five are Wasm cells: two judges, the grant ledger, identity and keys. A change to any of them needs the passkey on the exact candidate bytes. An owner grant must carry an Ed25519 and an ML-DSA-65 signature. `server/ball-transition.mjs`, `deploy/cloudflare/src/owner-grant-policy.mjs`, `packages/client/ui-layout/src/client/spatial/aumlok/head-promotion.ts`. Tests: `deploy/ci/authority-preflight.test.mjs` (10 cases), `hybrid-envelope.test.mjs` (6 cases).

### The organism: organs, balls, the scion and Pearl

An organ is one replaceable module of her; a ball is the manifest that lists every organ by hash; an epoch is the ball's version number. Organs are in `mirror/home/auma/seed/organs/`. Runtime code is in `packages/experimental/webworker-runtime/src/x6/` and its tests in `packages/experimental/webworker-runtime/tests/x6/`.

- **The genesis head.** RECORDED RUN (of an earlier tree): the dry run printed its ball id at epoch 1, and the local host answered it. The test that asserts a long-running node's head (`organ-entry-states.spec.ts`, "her real head") is known red for that reason. Every node starts from the same head: epoch 1, no parent, 26 entries, author `genesis` (`mirror/home/balls/HEAD.json`), with the Pearl suite and six scars (recorded failures, each with its lesson). What a node grows after that is its world, which `.gitignore` keeps out of the repository.
- **Balls and epochs.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree). A ball is a manifest that lists every organ by the SHA-256 of its code, and its id is its own hash. A new head must name the current ball as parent and be exactly one epoch higher. A stale caller gets `REBASE_REQUIRED`. `server/ball-head.mjs`, `deploy/cloudflare/src/head-do.mjs`. Test: `server/ball-manifest.test.mjs` (6 cases).
- **She stages her own next version.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree); no staging on a deployed node recorded. Three tools stage it for the owner. `stage_organ_promotion` changes one organ, and `stage_organ_set_promotion` adds one to eight ordinary organs. Each clones the live head, adds one epoch and posts the candidate to `/_head/stage`. `stage_head_promotion` writes one governance candidate to a review file for the owner. None of them publishes or approves. `ball-loader.ts`. Test: `stage-organ-promotion.spec.ts` (10 cases).
- **Live self-change with an undo.** IMPLEMENTED for `tree_patch` and `tree_undo` (exercised by `head-promotion.spec.ts`, 34 cases, and `open-tab-adoption.spec.ts`, 17 cases; green in the RECORDED RUN (of an earlier tree)). `self_apply` and `self_undo` have no test that calls them: UNVERIFIED. `tree_patch` mounts or hot-swaps one organ in the running agent without a page reload, and a failed activation is rolled back. `tree_undo` returns an organ to its previous version and disposes what it had registered, last first. `self_apply` stores new code and swaps it in as one step, and `self_undo` reverts the last change. `ball-loader.ts`.
- **The scion and one self-build step.** UNVERIFIED: no test in the tree calls the compiler in `scion.ts` or the organ `seed-cycle.js`; the code that joins them is tested in `scion-growth.spec.ts`. `scion.ts` takes up to 128 source files and 2 MiB and compiles them with a pinned offline esbuild-wasm in a separate worker. Compiling does not run or select the result. `seed-cycle.js` then writes the organ, hashes it, installs it, runs its acceptance cases, and keeps it or undoes it. The `scion_grow` tool joins the two (`scion-growth.ts`).
- **Pearl, and tests that attack the judge.** IMPLEMENTED; `server/pearl.test.mjs` green in the RECORDED RUN (of an earlier tree). Not proven containment, and self-attested: a deployed HEAD does not read Pearl's result (`deploy/cloudflare/src/head-do.mjs`: the deployed Durable Object supplies no `verifyTransitionQualification`). Pearl is what she keeps from breaking things: a retention suite, and founding lessons called scars. A retention suite of 23 cases and six scars ship as seed files (`mirror/home/auma/seed/pearl/retention-suite.v1.json`, `mirror/home/auma/seed/scars.jsonl`). Each scar records a failure and its lesson. Five of the six name the checks that now guard them, 14 in all, and every one of the 14 is a case of the suite. `scar-aura-silent-calm` names none yet. `seed-pearl.js` runs two builds of an organ against the whole suite in a disposable trial worker. In `scion-growth.spec.ts` (73 cases, one on the known-red list) a candidate tries to post a forged pass, and the parent ignores worker pass flags and grades the outputs again. Also `server/pearl.test.mjs` (38 cases).
- **The retention runner keeps its own record.** IMPLEMENTED; added after the RECORDED RUN (of an earlier tree), so not in it. When a candidate is run against the retention suite, the runner itself records import, guard, dependency, factory, export, setup and timeout failures, also when candidate code catches or rewrites them, and only the mounted, active `seed-pearl` of the exact head can record an admission. The package README says this is not an isolation boundary. `scion-growth.ts`, `packages/experimental/webworker-runtime/README.md`. Tests: `retention-infrastructure.spec.ts` (8 cases), `retention-runtime-parity.spec.ts` (11 cases), `retention-export-admission.spec.ts` (9 cases), `retention-real-head.spec.ts` (4 cases).
- **Receipts, predictions and Aura.** IMPLEMENTED. Partly red: `server/aura.test.mjs` is green in the RECORDED RUN (of an earlier tree); `server/receipts.test.mjs` failed 6 cases there, `server/receipts-policy.test.mjs` 3 and `server/predict.test.mjs` 6, all listed with cause not investigated. `seed-receipts.js` keeps a hash-chained receipt log with Ed25519-signed checkpoints. `seed-predict.js` seals a prediction about the next promotion as a receipt before anything changes, and stores no score: readers recompute surprise from the chain. `seed-aura.js` computes her coherence by fixed rules, and its authority tier is always `peripheral-hint`. Tests: `server/aura.test.mjs` (16 cases), `server/receipts.test.mjs` (10 cases, 6 on the known-red list).
- **25 sealed Wasm cells.** IMPLEMENTED for the loader; green in the RECORDED RUN (of an earlier tree). 24 of the 25 cells ship as binaries without source. Each file in `apps/web/public/cells/` is pinned by size, SHA-256 and a fuel grant in `wasm-cells.ts`. The loader admits a cell in a fixed order and stops at the first failure: the size, the hash on a private copy, then the memory limits read from the binary (one unshared 32-bit memory with a declared maximum), all before it compiles. Then it requires zero imports and exactly the metered export set. Every call runs on a fresh fuel grant in a separate worker that is ended after 5,000 ms, and the live memory is checked again after every call. The cells hold identity, keys, four judges, the grant ledger, risk, memory policy, Nostr signing and encryption, and layout. She calls them with the `x6_cell` tool. One cell, skillsmith, compiles WAT text into a new metered cell: `aura-focus.wasm` is built that way from `aura-focus.wat`, and `server/aura-focus-cell.build.mjs` exits 1 if the checked-in bytes differ. Test: `wasm-cells.spec.ts` (13 cases).
- **26 tools.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree). The outward tools were not run against a deployed node: UNVERIFIED. Besides staging and self-change, the loader registers tools for self-inspection (`x6_capability_index`, `x6_browser_estate`, `auma_snapshot`), outward reach through host-held doors (`x6_repo`, `x6_github`, `x6_cloudflare`, `x6_web_eyes`), advice from up to six other models at once (`x6_consult`), up to six parallel subagent tasks (`x6_swarm`), durable wishes with an acceptance and a step limit (`x6_wish`) and her Nostr identity (`x6_nostr`). `ball-loader.ts`. Test: `capability-index.spec.ts` (6 cases).
- **Waking with no tab open.** IMPLEMENTED; green in the RECORDED RUN (of an earlier tree); UNVERIFIED on a deployed edge. A Durable Object alarm can wake her for a bounded session: 3 rounds, 6 tool calls, 15 seconds (`CLOUD_WAKE_LIMITS` in `deploy/cloudflare/src/head-do.mjs`). `deploy/cloudflare/src/cloud-wake-tools.mjs` adds three read-only repository tools and one model turn through `deploy/cloudflare/src/cloud-model-door.mjs`, and itself writes, stages, promotes, approves and publishes nothing. The wake runs a model only under the exact setting `WAKE_EXECUTOR_ENABLED=1` (`deploy/cloudflare/README.md`). Tests in `deploy/cloudflare/src/__tests__/`: `cloud-wake-bounds.test.mjs` (23 cases), `cloud-wake-off-switch.test.mjs` (5 cases). The open-tab side is `wake-loop.spec.ts` (11 cases).

### The edge: one Worker, HEAD and MIRROR

HEAD is the edge store that selects which ball runs; MIRROR is the edge store that holds a copy of her home. Code is in `deploy/cloudflare/src/` and tests in `deploy/cloudflare/src/__tests__/` unless a longer path is given. No deployment of this tree is recorded.

- **One Worker, two Durable Objects.** IMPLEMENTED; `head-hardening.test.mjs` green in the RECORDED RUN (of an earlier tree), `worker.spec.ts` failed 5 of 98 there (listed). `worker.mjs` (2,124 lines) checks who is calling and routes. Tests: `head-hardening.test.mjs` (20 cases), `worker.spec.ts` (96 cases as written, 98 when run, since some are made in a loop; 5 are on the known-red list).
- **A thread log, and one writer at a time.** IMPLEMENTED; added after the RECORDED RUN (of an earlier tree), so not in it; not run on a deployed edge.
