# Kyber Shield：儿童安全与私人通信开放研究

[English](KYBER-SHIELD.md) | 中文

## 概述

**DIRECTION。** Kyber Shield 探索个人拥有的 AI（人工智能）能否在保护私人通信与人类决策权的同时，帮助年轻人抵御诱骗、性剥削和胁迫。方案结合明确的联系权限、范围受限的本地辅助和自愿举报。本文公开研究方向，供他人检视；它不提供已部署的保护服务，也不宣称已经证明有效。

<a id="the-proposed-system"></a>

## 拟议系统

本节机制均属 **DIRECTION**，引用外部研究的说明除外。

### 先有联系权限，再有联系

拟议的 Vanguard 青少年账户明确规定谁可联系它，以及哪些媒体可以呈现。人类签名邀请可提供有据可查的介绍路径，而范围受限的能力权限决定是否交付内容。邀请证明一次介绍，不证明对方是唯一的真人或值得信任的人。密钥失窃、胁迫、串通和恶意邀请者仍属于威胁模型。

### 权限分离的本地帮助

方案区分**查看**、**保留**、**传输**和**训练**权限。获准检查收到内容的本地助手，不会因此获得存储、上传或用于训练的权限。封闭的 Wasm 计算单元是候选实现组件之一；可信宿主、模型加载器、内存存储、更新和操作系统同样需要审查。无导入模块不等于物理隔离的设备。

候选响应包括私人辅导、临时模糊媒体，以及仅向年轻人展示的解释。是否联系可信任的成年人，应由明确且具体的选择决定。设计必须考虑施虐监护人、无法安全联系父母的儿童，以及紧急情况下获取人类支持的途径。监护权不等于持续读取年轻人日记的权利。

### 长期语境，不作自动指控

研究关注助手能否从持续对话中识别施压、孤立与胁迫模式，同时区分惊喜礼物或敏感私人问题等无害情境。精确、带类型的本地状态，可让观察与判断过程接受复查，但不能保证解释永远正确。

任何模式模型都需要经同意且合法的评估数据、明确的保留期限，以及独立的儿童保护审查。本次公开内容不包含非法材料、儿童私人对话或对真实个人的指控。合成示例可以测试程序行为，却无法证明现实检测准确率。模型评分绝不会成为虐待的证明、警方报告，或永久封禁账户的授权。

### 由接收者选择的举报

[消息存证（Message franking）](https://eprint.iacr.org/2017/664)研究加密通信系统中针对选定滥用消息的密码学举报。具有承诺性质的认证加密，可支持接收者在收信后不能任意篡改的举报。将此类协议用于 X7，需要精确的安全模型、经过审查的构造，以及明确说明谁能够验证举报。

仅有负载哈希无法确定发送者。有效签名在协议假设下确定与某个密钥的关系，而非使用该密钥的人的身份、意图或罪责。选择性披露必须保护无关对话。任何具有重大后果的处置流程，都必须考虑复核、申诉、密钥失窃和恢复。

### 随成长而独立

拟议的 Vanguard 到 Unbound 过渡结束监护人控制，让本人掌握自己的身份与历史。年龄核验、当地要求、争议、密钥丢失和恢复需要明确策略。生日字段或监护人签名不能单独解决这些问题。过渡不能让监护人保留隐蔽访问权，或扣留某人终身的数据。

<a id="what-must-be-demonstrated"></a>

## 必须证明的事项

**DIRECTION。** 以下是未来研究的验收问题，并非本文已经通过的测试。

| 领域 | 所需证据 | 必须明确展示的失败 |
| --- | --- | --- |
| 私密计算 | 公开源码、可复现构建，以及数值、时序、输出长度、静默和调用次数泄漏测试 | 合法端口 schema 仍可能泄漏信息。 |
| 人类联系 | 针对邀请农场、失窃密钥、串通和不受欢迎的投递进行对抗测试 | 邀请谱系不保证免于女巫攻击。 |
| 辅助质量 | 独立审查的合法数据集、误报与漏报测量、年龄及语言覆盖和对抗评估 | 合成案例成功不等于现实对话中的保护。 |
| 举报 | 审查过的协议、篡改及虚假举报测试、选择性披露与密钥失窃处理 | 真实字节仍可能被误解或缺乏语境。 |
| 人类控制 | 撤销、监护人滥用、安全求助、申诉、导出和恢复演练 | 保护功能本身也可能成为胁迫工具。 |
| 整体系统 | 独立的安全与儿童保护评估，涵盖宿主、更新、存储和设备入侵 | 仅靠 Wasm 隔离不构成端到端隐私。 |

方案认真对待 [Bugs in our Pockets](https://arxiv.org/abs/2110.07450) 记录的风险：将检查移到设备上，本身不会阻止监控、规避或用途扩张。成功的设计必须展示其受限权限与失败行为，不能假定本地处理已经解决这些风险。

<a id="kyber-kernel-and-the-evidence-limit"></a>

## Kyber Kernel 与证据边界

**UNVERIFIED — 作者报告的实验室工作。** 提供的 Kyber Kernel 指南报告了跨引擎检查点恢复、精确整数计算、观测的数学局限、独立 Wasm 内存、通过许可端口泄漏信息，以及经校验字节的光学传输实验。本次贡献不包含底层实验工具、完整输出或独立复现。因此，本文不将报告中的数值结果表述为公开 X7 代码树的实测事实。

拟议联系十分明确：计算可以产生提案或观察，但许可保持在计算之外。在数学模型中，若两个合法状态对所有允许的观测产生相同结果，却对问题给出不同答案，就能证明无法从这些观测推断答案。这不能证明一个人的意图，也不能消除语言模型的不确定性。

Kyber Kernel 是该运行时研究的项目名称。它不表示该设计就是 ML-KEM/Kyber 密码算法，也不构成后量子安全声明。
